## Что это за проект

Vasyavig — desktop-редактор markdown/YFM на Tauri 2 + React 19 + Zustand +
Vite + Gravity UI markdown-editor. Основной сценарий — harness-документация:
реестр документов, граф связей, ULID-ссылки `harness-ulid:`, конверты, задачи,
TOC. Phase 8 добавляет ассистента по документам; модель — в периметре, по
OpenAI-совместимому протоколу.

## Реализовано в 8.4

- Рендер тела письма детерминированный: `@diplodoc/transform`
  (`supportGithubAnchors`) → чистка chrome трансформа → подмножество YFM

  `stream:false`, json_mode по capability, runId/cancel, один repair-retry, затем
  fallback «subject = имя документа» с notice. Тело письма модель не пишет.
- Экспорт без записи в исходник: превью (эфемерная вкладка HtmlViewer), сохранение
  `.html` через нативный диалог (`saveEmailHtmlDialog`), копирование rich HTML.
- Audit: операция `email_html`, только метаданные.
- UI: `EmailResultCard` (subject/preheader, предупреждения, действия), кнопка
  панели с защитой от параллельных прогонов; i18n ru/en.

## Ключевые решения и ограничения

- Полный список решений 8.1/8.2 — в `harness_checkpoints/20261102_003_checkpoint.md`,
  решения 8.3 — в `20261102_004_checkpoint.md`; здесь только новое 8.4 и миграция.
- Тело письма не генерируется моделью: письмо — детерминированный экспорт
  документа + тема/preheader от модели. Причина: модель не должна переписывать
  содержимое документа (тот же принцип, что в 8.3: фиксы строит код, модель
  только объясняет).
- Fallback при невалидном ответе модели — «subject = имя документа», письмо
  всё равно собирается (ценность не зависит от модели).
- Миграция путей выполнена перезаписью байт-в-байт, а не редактированием:
  diff — только строки с путями, форматирование и переводы строк не тронуты.
- Короткие формы `_tasks_/`, `_checkpoints_/` в прозе не переписаны — так же,
  как в эталоне `lm_hrdo_2` после его миграции.
