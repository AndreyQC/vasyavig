## Главное этого захода

Пользователь увидел «Ответ модели не прошёл валидацию: Ответ модели пуст».
Диагностика (захват реального тела ответа + проба штатного кода) показала:

| Слой | Проверка | Итог |
|---|---|---|
| Эндпоинт | сырое тело ответа `minimax-m2` | 2804 байта, `finish_reason: "stop"`, валидные вердикты ✅ |
| Провайдер | `runChat` на этом теле | текст извлечён ✅ |
| Валидация | `parseVerdicts` | ok, 2 вердикта ✅ |
| **Доставка Rust → webview** | — | **терялась** ❌ |

**Корень (D-4, P1):** Rust отдаёт чанк в Tauri-канал как JSON `{"data":[…]}`;
при JSON **> 8192 байт** (`MAX_JSON_DIRECT_EXECUTE_THRESHOLD`, tauri 2.12.4) Tauri
уходит в асинхронный fetch вместо синхронного `eval`. Команда `stream_chat`
при этом завершается, `invoke` резолвится, фронтенд закрывает буфер ответа —
а вебвью догружает тело уже после. Короткие ответы (< ~2 КБ) доставлялись
синхронно, поэтому баг проявлялся редко и выглядел как «модель не отвечает».

**Исправление:** маркер конца потока `StreamChunk.end` из Rust + ожидание
`awaitChannelEnd()` на фронте (данные приходят по индексу, порядок сохраняется).
