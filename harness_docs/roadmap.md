## Phase 4 — Кириллица в ссылках и авто-оглавление (маленькая фаза)

Контекст (исследование 2026-08-27): редактор открывает markdown в WYSIWYG;
markdown-it при парсинге процент-кодирует не-ASCII в URL (`normalizeLink`),
Gravity-сериализатор записывает href как есть. Итог: переключение режимов или
любая правка делают вкладку dirty, а Ctrl+S переписывает файл с якорями вида
`#1-%D0%B2%D0%B2%D0%B5%D0%B4%D0%B5%D0%BD%D0%B8%D0%B5` вместо `#1-введение`.

| # | Задача | Суть | Проверка |
|---|---|---|---|
| 1 | Фикс перекодирования | Расширение редактора через публичное API `builder.configureMd`: `md.normalizeLink = (u) => u` (+ `normalizeLinkText`) — URL не кодируются при округлении WYSIWYG | Переключение WYSIWYG -> Markup не делает вкладку dirty; после правки и сохранения якоря не меняются |
| 2 | Кнопка «Восстановить кириллицу в ссылках» | Утилита по активному markdown-файлу: декодировать %-последовательности не-ASCII в URL (якоря, пути картинок) безопасным `decodeURIComponent` с fallback; правки вносить через редактор (undo сохраняется), вкладка становится dirty — сохранение за пользователем | Файл со смешанными якорями: `#1-%D0%B2...` -> `#1-введение`; валидные escape-последовательности не-URL текста не трогаем |
| 3 | Кнопка «Составить оглавление» (TOC) | Прочитать заголовки документа (H1–H4), сгенерировать список `- [Заголовок](#якорь)` со слагами в том же формате, что даёт превью (`@diplodoc/transform`, GitHub-style, кириллица сохраняется); вставить или заменить существующий блок оглавления | На конвертированном ТЗ клики по пунктам в превью ведут на разделы; повторная генерация не дублирует блок |

Открытые вопросы (решить в плане фазы, `_tasks_/`):

- Диапазон уровней заголовков в TOC (все H1–H4 или настраиваемо).
- Заменять существующий блок «Оглавление» целиком или только вставка.
- Куда положить кнопки (тулбар редактора / меню) и нужны ли горячие клавиши.

## Беклог (вне фаз, приоритет уточняется)

- **Notion-подобные таблицы** — целевой формат хранения: YFM `{% table %}` с
  директивами `{% colwidth=[N] %}` (пример — в запросе пользователя 2026-08-31).
  По исследованию 2026-08-31: формат НЕ поддерживается текущими версиями
  `@gravity-ui/markdown-editor` (15.44) и `@diplodoc/transform` (4.77) — обе
  понимают только `#|`-синтаксис и не хранят colwidth; потребуется собственный
  markdown-it-парсер/сериализатор, расширение схемы (`colwidth` на ячейках) и
  плагин превью. Notion-UX частично готов встроенным YfmTableControls («+»
  вставка строк/колонок, DnD, меню ячейки). Крупная фаза; идеи — gramax §3
  (`harness_docs/GRAMAX_RESEARCH_RESULT.md`).
- Ручки ресайза картинок в WYSIWYG: перетаскивание рамки (наш nodeView перекрыл
  React-view ImgSize; вернуть композицией).
- Вставка картинок из буфера и перетаскиванием на окно редактора (write path:
  файл в `<имя>_assets/` + относительный src).
- Lazy-loading и индикатор битых картинок.
- **Mermaid в WYSIWYG** — рендер диаграмм в редакторе + модалка исходника с
  Monaco и live preview (наработки gramax: `harness_docs/GRAMAX_RESEARCH_RESULT.md` §2)
  — реализовано в change `20260904-mermaid-wysiwyg`; осталось: миграция
  SplitPreview на общий рендерер (активирует код-сплит mermaid ~1 МБ),
  подсветка синтаксиса mermaid в Monaco-модалке, lazy-рендер по viewport.
- **Работа с git** — при открытии папки, содержащей репозиторий: status,
  commit, pull, push и базовые операции из UI (запрос пользователя 2026-08-31).
- **Реакция вкладок на внешние изменения файлов** — единый механизм для
  markdown- и text-вкладок: watcher-событие по пути открытой вкладки
  перечитывает не-dirty вкладку, для dirty — промпт «перезагрузить /
  оставить» (решение пользователя 2026-09-03: отложено из change
  `20260903-file-viewers-text-edit` в отдельный change).
