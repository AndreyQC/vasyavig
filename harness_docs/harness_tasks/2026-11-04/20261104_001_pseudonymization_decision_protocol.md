Спайк `ru-compromise` на русском тексте: `#Person → [Иван, Иванович, Иванов,

Ограничения (подтверждены): `#Organization` — 0 %, `#City` в родительном падеже
(«в г. Москве») — 0 %, «Санкт-Петербург,» приходит с запятой.

### 2.4. Правила для русского — свои, проверены исполнением

| Признак | Полнота | Ложные срабатывания |
|---|---|---|
| Отчество (`-ович/-евич/-ич`, `-овна/-евна`) | ~95 % персон | **<1 %** |
| Инициалы + фамилия (`Петров А.С.`, `И. И. Иванов`) | ~90 % | ~2 % |
| Юр. формы (ООО/АО/ПАО/НАО/ФНС/ГК) | ~85 % орг | ~2 % |
| Гео-подсказка + предлог (`в г. Москве`, `на ул. Пушкина`) | ~70 % локаций | ~10 % (нужна пост-фильтрация «улица ≠ город») |
| Гео-словарь (из ru-compromise) | ~90 % городов | ~1 % |
| Бренды без юр. формы (Газпром, Сбербанк) | **0 %** | — нужен доменный словарь |

**Техническая ловушка:** в JS `\b` и `\w` не работают по кириллице
(`/(\bИван)/.test("Иван Иванов") === false`). Любой русский regex обязан
использовать lookaround `(?<![А-Яа-яЁё])…(?![А-Яа-яЁё])`.

Рычаг расширения: `ru-compromise` умеет `nlp.addWords({'Ромашка':'Organization'})`
— доменный словарь (контрагенты, филиалы) подгружается в рантайме, без
пересборки бандла.

## 4. Решения и обоснования

**D1. ML-детектор в roadmap не входит.** GLiNER — 349 МБ int8 (1.17 ГБ в
оригинале) при инсталляторе 9.8 МБ; версия из ссылки нашего чата —
CC-BY-NC-4.0 (некоммерческая); качество единственного компактного варианта на
карточке не опубликовано, домен — новости, а не документация. Возврат к
вопросу возможен отдельной задачей при выполнении условий §7.

**D2. Основа NER — правила, а не модель.** `ru-compromise` + `lvovich` +
~100 строк своих regex ≈ **120 КБ gzip** к текущему бандлу (~9 МБ), без wasm, без
Python, оффлайн по умолчанию. Прецедент в проекте — `spell_service.rs`
(словари `include_str!` ~4.1 МБ, ленивая инициализация через `OnceLock`, свой
`tokenize()` с офсетами).

**D3. NER — сменный детектор, а не отдельный механизм.** Интерфейс детектора
общий для секретов и NER; добавление NER = добавление одного детектора в
реестр, без изменения каркаса маскирования.

**D4. Формат плейсхолдеров — `[[VAS_<TYPE>_<N>]]`** (с префиксом `VAS_`:
снижает риск коллизии с текстом документа; §3.9 спецификации и §7 сводки
расходятся в формате — здесь закреплён префиксованный). Дополнительно —
проверка коллизии разделителя с текстом документа (§3.9 п.2). Одна сущность —
один плейсхолдер в пределах прогона.

**D5. Граница T1 — ядро без UI.** Первая задача: детекторы, маппинг,
маскирование контекст-пака, валидация, unmask, audit. Превью отправки
(чипы, подтверждение) — отдельная задача **T1b**. До T1b маскирование
выключено по умолчанию — состояние безопасно.

**D6. Семантика режима `preview` до T1b.** Маскирование применяется, но
пользователь не подтверждает отправку; в панели — явное предупреждение, что
предпросмотра ещё нет, в audit — отметка, что подтверждения не было.
Гарантия «секреты не уходят в модель» соблюдается; теряется только
возможность перепроверить содержимое отправки.

**D7. `emailHtml` — без маскирования.** По §3.9: «для задач, где важны реальные
значения (письмо с именами, ссылки), псевдонимизацию нужно отключать».
Механизм доступен, режим для письма — `off`.

**D8. Маппинг — только в памяти.** Таблица соответствий не попадает в лог, в
audit и на диск; в audit идут только счётчики и типы сущностей.

## 7. Условия возврата к ML-детектору (отложено)

1. Правил не хватает: нужна связывание сущностей (PERSON в свободном тексте,
   «Иван пришёл, а Маша ушла» правилами не вытянуть).
2. Домен документов совпадает с доменом обучения модели.
3. Готовность поставить модель **отдельным необязательным пакетом**, чтобы
   базовый клиент остался ~10 МБ; Apache-2.0-вариант (не CC-BY-NC).
4. Есть замеры на целевой машине: время на 100/500 КБ, память, время первой
   загрузки.
5. Машина состояний готова: `disabled | unavailable | loading | ready | error`,
   деградация к правилам, таймауты, отмена, кнопка «Проверить окружение».
