## 1. Цель и границы

**Цель.** Секреты и PII не уходят в модель: детерминированные детекторы
находят чувствительные значения, реестр прогона даёт стабильные алиасы
`[[VAS_<TYPE>_<ULID>]]`, контекст-пак маскируется перед отправкой, ответ
модели валидируется и размаскировывается; в audit — только счётчики и типы.

**Не входит** (следующие задачи): превью отправки (T1b), NER-детектор (T2),
инлайн-разметка `vas-entity:` и ручная разметка (T3), re-markup и
производный индекс (T3b).

## 2. Решения

| # | Решение | Обоснование |
|---|---|---|
| R1 | Дефолт `masking.mode` меняется `preview` → `off` на время T1; вернуть `preview` в T1b (когда появится UI подтверждения) | D5: до превью маскирование выключено по умолчанию — не создаём иллюзию подтверждённой отправки |
| R2 | Семантика `preview` до T1b: маскирует без подтверждения; в audit-записи — `confirmation: "none"` | D6; гарантия «секреты не уходят» соблюдается уже в T1 |
| R3 | Алиас `[[VAS_<TYPE>_<ULID>]]`, ULID — генератор прогона; в T3 ULID сущности станет постоянным (из href `vas-entity:`), для документов без разметки per-run ULID — fallback | D4'; интерфейс реестра одинаковый для обоих источников |
| R4 | В промпт — маскированный текст + правило «сохраняйте плейсхолдеры дословно»; словарь «алиас → тип» (D9) — одной строкой в системном сообщении рецептов | модель должна понимать семантику алиасов, не видя значений |
| R5 | Детектор `secrets` маскирует **только значение** `KEY=value`, имя ключа остаётся видимым | модель понимает контекст («это API-ключ»), значение не утекает |
| R6 | Русские ключи в `KEY=value` тоже ловятся (`пароль=`, `токен:`, `секрет=`) | язык документации — русский (конвенции репо) |
| R7 | В regex — только lookaround `(?<![А-Яа-яЁё…])…(?![…])`, `\b` запрещён | ловушка JS: `\b`/`\w` не работают по кириллице (проверено) |
| R8 | Пересекающиеся спаны: longest-wins, детерминированная сортировка | URL с credentials внутри `KEY=value` и т.п. |
| R9 | Коллизия разделителя: если `[[VAS_` встречается в тексте — реестр выбирает альтернативный префикс из фиксированного списка; активный префикс знает unmask | D4 (проверка коллизии §3.9 п.2) |
| R10 | Мультистрочные спаны (PEM-блоки) — наравне с однострочными | маскирование по offsets |
| R11 | `emailHtml` — без маскирования в T1 (`off` для рецепта) | D7: письмо с реальными именами — псевдонимизация отключается |

## 4. Критерии приёмки

- [ ] round-trip mask/unmask на фикстурах ru/en: значение восстанавливается байт-в-байт
- [ ] одно и то же значение → один ULID/алиас в пределах прогона (R3)
- [ ] `KEY=value`: ключ видим, значение замаскировано (R5), русские ключи ловятся (R6)
- [ ] PEM-блок (мультистрока) маскируется целиком (R10)
- [ ] пересечение спанов разрешается longest-wins детерминированно (R8)
- [ ] коллизия `[[VAS_` в документе → альтернативный префикс, round-trip сохраняется (R9)
- [ ] неизвестный алиас в ответе → `scanUnknownAliases` его возвращает; потерянный — `missingAliasIds` (сырьё блокировки apply)
- [ ] дефолт конфига — `off`; при `off` текст не изменяется ни одним байтом
- [ ] в audit-структурах нет значений (только счётчики/типы)
- [ ] `pnpm test`, `npx tsc --noEmit`, `npx vite build` — зелёные

## 6. Риски

- Модель перефразирует/теряет алиас → в T1c: notice + блокировка авто-apply
  (валидация уже возвращает сырьё). Полный remap не гарантирован (§3.9) —
  осознанное ограничение.
- Ложные срабатывания детекторов (телефон vs число документов) → минимальные
  якоря форматов; отключение детектора — конфигом (`masking.detectors`).
- Ручная разметка (T3) в будущем перекроет большую часть потребности —
  детекторы остаются страховкой для неразмеченных документов.
