## Что сделано

**Корень**: `ensureRelationsIndex` кэширует по ключу каталога; в harness-режиме
каталоги «корень репо» (панель) и «каталог документа» (скан) резолвятся в один
файл `harness_docs/harness_index/relations.jsonl`. `writeRelationsIndex`
обновлял только объект вызывающего ключа → sibling-ключ скана (созданный до
появления файла — пустой) оставался устаревшим → резолвер по связям мёртв до
перезапуска.

**Фикс** (зеркало механизма сущностей, как решено в журнале):
- `entityRelations.ts`: `invalidateRelationsIndex(path)` — сбрасывает все
  кэш-ключи, чей нормализованный путь файла совпадает (суффикс
  `relations.jsonl` guard, как у `invalidateEntitiesIndex`); вызывается из
  `writeRelationsIndex` после записи.
- `useFileWatcher.ts`: тот же вызов на `fs-change` рядом с
  `invalidateEntitiesIndex` — внешние правки файла (make/git/bot; сценарий
  R-12) больше не оставляют stale-кэш.

Уведомлений подписчиков (notify-шина как у сущностей) не потребовалось:
панель обновляет своё состояние сразу после write; кросс-ключевая свежесть
обеспечивается перечитыванием с диска.

## Тесты (+2, всего 768 passed)

`entityRelations.test.ts`, new describe D-9 (fs mocked, harness-фикстура):
- флагман: `ensure(DOC_DIR)` (пустой кэш до файла) → `write` через ключ корня
  → `ensure(DOC_DIR)` обязан увидеть связь. **Красность подтверждена**: с
  закомментированным вызовом инвалидации тест падает на точном ассерте.
- изоляция: `invalidateRelationsIndex(REL)` сбрасывает только ключи этого
  файла (ключ другого каталога остаётся тем же объектом).
