# D-9 (P1): кэш relations не инвалидируется при записи — план

> Дата: 2026-11-09
> Контекст:
> - `harness_docs/harness_tasks/2026-11-08/20261108_001_gui-acceptance-t6-t4_dialog.md` — журнал приёмки, дефект D-9 (шаг D1, 21:2x + повтор)
> - `harness_docs/harness_checkpoints/20261109_001_checkpoint.md` — P1-фиксы: D-17 ✓, D-7 ✓, далее D-9

## Symptom (из приёмки)

Связь `T47→Ромашка works_at explicit` записана (файл на диске проверен),
но перескан конфликтов показывает «разрешимых: 0» — резолвер по связям мёртв
до перезапуска приложения. После перезапуска — «разрешимых: 2» (подтверждён).

## Корень (диагностика 2026-11-09)

- `ensureRelationsIndex` (`entityRelations.ts:262-293`) кэширует по **ключу
  каталога**; в harness-режиме разные каталоги (корень репо и каталог
  документа) резолвятся в один и тот же путь
  `<root>/harness_docs/harness_index/relations.jsonl`.
- Скан создаёт запись кэша под ключом «каталог документа» ДО появления файла
  → пустой список, навсегда.
- `writeRelationsIndex` (`entityRelations.ts:301-307`) обновляет только
  переданный объект (ключ «корень репо», панель) — sibling-ключи не
  инвалидируются.
- У сущностей аналог закрывает watcher: `invalidateEntitiesIndex(path)`
  сбрасывает все ключи с совпадающим путём файла (`entitiesIndex.ts:237-247`),
  вызывается из `useFileWatcher.ts:35`. Для связей ни инвалидатора, ни
  строки в watcher нет.

## Фикс (зеркалить механизм сущностей — решение из журнала)

1. `entityRelations.ts`: `invalidateRelationsIndex(path)` — по суффиксу
   `RELATIONS_FILE_NAME`, сброс всех кэш-ключей с тем же нормализованным
   путём файла.
2. `writeRelationsIndex` вызывает инвалидатор ПОСЛИ обновления своего объекта
   (запись на диск уже произошла — другие ключи перечитают свежее; тесты без
   Rust-watcher тоже закрываются).
3. `useFileWatcher.ts`: рядом с `invalidateEntitiesIndex(path)` —
   `invalidateRelationsIndex(path)` (внешние правки: make/git/bot, сценарий
   R-12).

Уведомления подписчиков (notify как у сущностей) не нужны: панель обновляет
своё состояние сразу после write, кросс-ключевая свежесть обеспечивается
перечитыванием с диска.

## Шаги

1. Красный тест `entityRelations.test.ts`: harness-фикстура (harness.yaml в
   корне); ensure(docDir) при отсутствии файла → пустой кэш; запись через
   ensure(root) + writeRelationsIndex; ensure(docDir) обязан увидеть связь.
2. Фикс 1–3; тест зелёный; существующие тесты (766) без регрессий.
3. Проверки: pnpm test / tsc --noEmit / vite build.
4. Result-док + статусы D-9 (сводка, журнал); коммиты код/docs раздельно; пуш.

## Риски

- Избыточный перечитывание файла после каждой записи — стоимость одна, на
  скан уже есть свой ensure-кэш; согласуется с поведением watcher-пути у
  сущностей.
- `relations.jsonl` вне harness-режима: разные каталоги → разные пути →
  инвалидатор no-op (корректно).
