## Symptom (из приёмки F1, 2026-11-08)

В конвейере «Проверить документ» правила-детекторы T6-9 **не срабатывают**:
валидные фикстуры СНИЛС / ИНН×2 / ОГРН / номер карты / IBAN (из `rules.test.ts`)
остаются открытым текстом и уходят к модели замаскированными лишь частично.
При этом маскируются email / телефон / токен и сущности справочника (включая
неразмеченное «Иванов…» → VAS_PERSON с ULID NH1 — резолвер работает).
WYSIWYG не менялся — режим preview ✓ (дефект только в маскировании).

## Уже сделанная диагностика (след из журнала, на паузе по решению пользователя)

1. Дефолт конфига содержит `"rules"` — `config.ts:148`.
2. Ветка detectText гейтится `enabled.has("rules")` — `detectors.ts:143`.
3. `detectorRules()` всегда включает встроенный корпус — `detectors.ts:26-28`;
   `harness.yaml` lm_hrdo_2 `entities.rules` не задаёт → корпус полный.
4. `entityTypeForRule` fallback → SECRET — `types.ts:39-41` → если бы правила
   выполнялись, они замаскировали бы хотя бы как SECRET.
   ⇒ **Вывод: правила НЕ выполняются** (или `enabled`-набор в рантайме без "rules").

## Гипотезы (ранжированы)

- H1: источник эффективного `maskingSettings.detectors` в GUI-конвейере — не дефолт
  `config.ts`, а сохранённый workspace-конфиг, где `"rules"` отсутствует в массиве
  detectors (рядом с `rep.vasyavig-workspace` файла конфига нет — откуда читается?).
- H2: конвейер «Проверить документ» вызывает отдельный путь маскирования, не
  проходящий `detectText` с rules-веткой (свой список детекторов).
- H3: правила выполняются, но результат отбрасывается ниже по потоку
  (dedup/приоритет/пересечение с уже замаскированными ranges).

## Шаги

1. **Диагностика**: найти источник эффективного `maskingSettings.detectors` для
   конвейера; при необходимости — временный лог `enabled`-набора в `detectText`
   (убрать до коммита) или unit-тест, воспроизводящий GUI-путь маскирования.
2. **Фикс**: устранить корень; каждый P1-фикс — отдельный коммит с тестом
   (rule: тест воспроизводит дефект до фикса и зелёный после).
3. **Проверки**: `pnpm test` (755+ passed), `npx tsc --noEmit`, `npx vite build`;
   GUI-перепроверка F1 на фикстурах правил (СНИЛС/ИНН/ОГРН/карта/IBAN).
4. **Документация**: `_result.md` к этой задаче + обновить статус D-17 в бэклоге
   (диалог приёмки — только строка статуса, без переписывания истории).
