## Что сделано

**Корень** (подтверждён красным тестом до фикса): `collectConflicts`
(`entityConflictStore.ts`) брал кандидатов из компилята (`match.ulids`,
склонённые формы через `expandEntityForms`), но `resolveRegistryForm`
(`entityResolution.ts`) заново выводил кандидатов через `matchesOfForm`
только по хранимым `canonical/forms/aliases`. Для формы, существующей лишь
как склонение, `matchesOfForm = []` → `resolution = null` → вхождение молча
пропускалось → UI «Конфликтов: 0» (флагман T6-5).

**Фикс** (по решению из журнала приёмки): `resolveRegistryForm` получил
опциональный параметр `precomputedCandidates`; `entityConflictStore` передаёт
уже отфильтрованных `candidates` из компилята. Перематчинга больше нет.
`matchesOfForm` остаётся exported-хелпером (его путь — вызовы без
компилят-матчинга; в проде таких не осталось, тесты сохранены).
`EntityResolution.conflict.candidates` → `readonly` (никто не мутирует).

   индекса целиком** (до merge с canonical). Первая версия теста на этом
   споткнулась (конфликт не возникал вовсе). Кандидат в будущий UX-таск /
   мелкий фикс индексатора.

   если компилят нашёл склонение двух записей, а stored-форма одна — теперь
   это конфликт (корректно по T6-5), раньше — молчаливый пропуск.
