## Три проявления одного корня

Сущностный матчинг идёт по **сырому** markdown; fenced-код (```/~~~) не
исключается, хотя `parseEntityLinks` и `markdownBlocks` фенсы пропускают
(одна и та же эвристика `FENCE_RE` в `entityContext.ts`):

1. **D-8** (P2): скан конфликтов активного документа — `collectConflicts` →
   `matchRegistryForms(content)` (`entityConflictStore.ts:132`): форма внутри
   ```text-фенса засчитывается («вхождений: 4» вместо 3).
2. **D-10** (P1): следствие — авто-якоря вставляют разметку в фенс;
   `parseEntityLinks` её там не видит → «не размечено» → рекурсивный скан
   вставляет слой поверх (~50 вложенных ссылок, остановлено флагом).
3. **D-19** (P2): bulk «Разметить все известные» (`NerButton.markAllKnown`)
   берёт вхождения из `useNerSpans` → `detectNer(content)` — тоже по сырому
   тексту → якорь влезает в фенс.

+ четвёртый контур, не названный в дефектах, но тот же корень: репо-скан
`scanRegistryForms` → `matchRegistryForms(file.content)` (`entityScan.ts:250`)
— ambiguous/unknownKnown считают вхождения во фенсах. (T3-era
`scanMarkdownContents` фенсы УЖЕ пропускает — прецедент и образец.)

## Фикс: единая примитив-зачистка

`entityContext.ts`: **`maskFencedCode(markdown): string`** — тот же `FENCE_RE`
и тот же toggle, что в `markdownBlocks`; содержимое фенсов (и строки-маркеры)
заменяется пробелами **с сохранением длины и переводов строк** → все смещения
вхождений вне фенсов остаются валидными, вхождения внутри физически
невозможны.

Применить в трёх точках (обернуть текст перед матчингом):
- `collectConflicts` (D-8/D-10): `matchRegistryForms(maskFencedCode(content))`;
  контекст-блоки (`blockAt(block.text)`) уже фенс-свободны.
- `scanRegistryForms` (репо-скан): `matchRegistryForms(maskFencedCode(...))`.
- `useNerSpans` (D-19): `detectNer(maskFencedCode(content))` — предложения и
  bulk наследуют зачищенный набор.

**НЕ трогать маскирование** (`agentStore`/`maskText`): privacy-first — имя в
код-блоке для промпта всё равно секрет; фенс-исключение только для
матчинга-как-навигации/разметки.

D-10 закрывается корнем (в фенс больше не вставляем); дополнительный guard
«позиция внутри vas-entity-ссылки» — не нужен: `overlapsMarked` уже сверяет
с `parseEntityLinks`, а повторный цикл невозможен, когда фенс-матчей нет.

## Шаги

1. `maskFencedCode` + юнит-тесты (сохранение длины/смещений, ``` и ~~~,
   открытый фенс, inline-код НЕ трогается).
2. Красные интеграционные тесты: конфликты (форма во фенсе → 0 конфликтов,
   авто-якорь не лезет в фенс); репо-скан ambiguous не считает фенс.
3. Точки 1–3 → зелёные. Хук `useNerSpans` — компонентных тестов нет (нет
   testing-library, как в чекпоинте) — проводка фиксируется типами/ревью;
   покрытие на уровне `maskFencedCode` + интеграция.
4. Проверки: pnpm test / tsc / build; result + статусы D-8/D-10/D-19; пуш.

## Риски

- Регресс: stored-конфликты/unknownKnown вне фенсов не должны измениться —
  существующие тесты (768) это чекнут.
- Пробелы вместо содержимого фенса в `detectNer`: переносы строк сохраняем —
  детекторы `pii.fio-ru` не склеят строки через границу блока.
