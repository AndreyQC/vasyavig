## Ключевые находки

1. **union-span вместо longest-wins** — не косметика: при отбрасывании более
   короткого пересекающегося спана его непересекающиеся байты оставались
   открытым текстом (часть значения утекала в промпт). Теперь пересечение
   объединяется в `[min, max)`, атрибуция — у длиннейшего.
2. **Валидаторы получают цифры, а не исходный текст** («112-233-565-01» →
   `11223356501`). Без `stripNonDigits` правило СНИЛС не срабатывало никогда.
3. **Строгое правило ФИО не ловит разговорные отчества** («Иваныч», «Ильич»):
   якорь точности — окончание отчества из списка (`ич|вн|ичн`). Такие формы
   понимает наш NER/склонялка (T3d) — это не регрессия, а разделение
   ответственности: правила дают precision, NER — recall.
4. **Regex-флаги RE2 не переносятся как есть**: инлайн `(?i)` (23 правила в
   корпусе) → поле `case_insensitive`; lookaround в корпусе не используется
   ни разу — конвертация ограничилась флагами.
5. **Префильтр по ключевым словам нельзя делать автоматически**: в guardrails
   он безопасен по доказанному анализу дерева `regexp/syntax`, в JS аналога
   нет → только явный флаг `prefilter_safe: true` (по умолчанию выключен).

## Известные ограничения / NOT done

- Встроенный корпус — **12 правил** из 46 в guardrails (взяты самые ценные для
  русских документов). Остальные (KPP, паспорт, адрес, CVC, gitleaks-секреты)
  не перенесены.
- **Markdown-сегментации нет** (как и в guardrails): правила видят весь текст,
  включая код-блоки и inline-код. Для подсветки в редакторе это даёт ложные
  срабатывания — нужен разбор Markdown (T6-3).
- Тип правила не может быть «неизвестным»: неизвестный → SECRET (privacy-first).
- `co_occurs`-связи как `relations.jsonl` не пишутся (профиль — в памяти,
  T6-1).

  это изменение поведения 8.5; GUI-приёмка (T4) должна быть перепроверена.
