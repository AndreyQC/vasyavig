## Условия

- `pnpm tauri dev` запущен (окно открыто), ветка `dev`.
- В workspace открыт любой harness-репозиторий; модель настроена (нужна для A5, E1, E2).
- Режим маскирования — preview (дефолт): модель не зовётся без подтверждения.

## Тестовый документ

Создать `t4-acceptance.md` в workspace и вставить:

```markdown
# T4: приёмка маскирования

Иванов Иван Иваныч согласовал договор с Петровой Анной Сергеевной
из ООО «Ромашка». Отчёт отправил Ивановым И. И. на почту
ivan.ivanov@example.com из Москвы.

Токен стенда: xoxb-fake-token-not-a-real-secret.
```

## Шаги

Отмечай статус после каждого шага: `ок` / `дефект` / `н/п` (не принято
из-за окружения). Комментарий — одной строкой, подробности в журнал.

### A. Маскирование и превью (кнопка «Проверить документ»)

| # | Действие | Ожидание | Статус | Комментарий |
|---|---|---|---|---|
| A1 | Открыть тест-документ, нажать «Проверить документ» | превью: чипы алиасов с типами, счётчики, маскированный текст; модель не зовётся | | |
| A2 | Кликнуть по чипу алиаса | раскрывается исходное значение (только в UI) | | |
| A3 | Нажать «Отменить» | превью закрыто, notice об отмене, отправки нет | | |
| A4 | Снова проверка; править текст ДО подтверждения; затем «Подтвердить и отправить» | ошибка «превью устарело», отправки нет | | |
| A5 | Проверка; сразу «Подтвердить и отправить» | модель зовётся с маскированным текстом; findings/вердикты | | |

## Правила

1. Шаг не пропускаем; если блокирует дефект — фиксируй и продолжай независимые шаги.
2. Дефект: краткое описание + что ожидал/что увидел. Скриншот по желанию.
3. Результаты сообщаешь в чат — агент переносит их в журнал и чек-лист.
