## T6-6. Re-markup → сверка «справочник ↔ тексты»

Секция «Репозиторий» в NER-дропдауне перестраивается:

| Было | Стало |
|---|---|
| changed / missing (по чипам) | остаются, но вторичны (подписи «по якорям») |
| unknown-known | **«в текстах, но не в справочнике»** — кандидаты на добавление |
| — | **«в справочнике, но не встречается»** — неиспользуемые |
| конфликты типов (T3e) | остаются |
| — | **«одна форма → несколько сущностей»** — неоднозначные (переход в T6-5) |

- Скан расширяется: ищем не только размеченные сущности, но и **вхождения форм
  справочника** в текстах (совпадение по формам + алиасам + склонениям).
- Результат — четыре списка с действиями:
  - кандидат → «В справочник» (T6-4);
  - неиспользуемый → «удалить» / «оставить»;
  - неоднозначный → открыть панель конфликтов (T6-5);
  - конфликт типов → как сейчас.

## T6-7. Миграция

| Что | Как |
|---|---|
| `forms` vs `aliases` | при пересборке индекса из разметки наблюдаемые формы идут в `forms`, ручные `aliases` сохраняются |
| Профиль `co_occurs` | считается сканом репо; кэш `cooccurrence.json` |
| Дубль «Ивановым И. И.» | слияние через панель справочника (T6-2): формы переезжают в основную запись, якоря в документах переписываются |
| Старые `entities.jsonl` | читаются как есть; `aliases` пуст, поле не пишется, пока не задано вручную |

## T6-8. Правило использования чипа

- Текст-подсказка в UI (тулбар/панель справочника): «Якорь нужен, когда
  одна форма = разные сущности, сущность связывает несколько документов, нужен
  якорь для маскирования/аудита или нужна стабильная ссылка».
- Якорь ставится: (а) вручную кнопкой «Сущность», (б) автоматически при
  разрешении конфликта (T6-5).
