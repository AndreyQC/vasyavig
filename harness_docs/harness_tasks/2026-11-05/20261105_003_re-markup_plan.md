## 1. Цель

Закрыть цикл re-markup из В9 (требование пользователя): правки документа →
прогон по документам репо → **changed** (та же сущность или новая — решает
пользователь), **неразмеченные** известные значения (предложить разметить),
**исчезнувшие** ссылки (вывести из реестра); производный `entities.jsonl`
пересобирается тем же сканом.

## 2. Решения

- **B-1. Скан репо** (`src/lib/entityScan.ts`, `scanEntitiesForRoot(root)`):
  - список .md — из дерева `fileStore.trees[root]`, если загружено; иначе
    рекурсивный `listDirectory` (скрытые и `node_modules` пропускаются);
  - каждый .md → `parseEntityLinks` → вхождения per-ULID
    `{doc, start, end, value, type}` (позиции raw-markdown);
  - NER по всему репо **не** запускается (дорого) — неразмеченные ищутся
    точным совпадением значений индекса (см. B-2); NER-предложения остаются
    документными (NerButton).
- **B-2. Diff с индексом** (`diffEntitiesScan(scan, index)`):
  - **changed**: вхождение, чья форма не найдена в `forms ∪ canonical` своего
    ULID — «значение изменилось: та же сущность или новая?» (В9 п.3);
  - **missing**: ULID индекса, у которого ноль вхождений во всём репо —
    кандидат на вывод (В9 п.в);
  - **unknown-known**: точные совпадения значений (`forms ∪ canonical`) в
    тексте .md **вне** разметки — «известная сущность, разметить?» с ULID из
    индекса (В9 п.а; связность без NER).
- **B-3. Store** (`src/store/entityScanStore.ts`): `byRoot: {scanning, at,
  scannedDocs, changed, missing, unknown}`, действия: `scan(root)` (скан +
  diff, кэш результата), `rebuildIndex(root)` (пересборка jsonl сканом:
  canonical — из старого индекса, иначе первая форма; запись одним write),
  `resolveChanged(root, change, decision)`:
  - **«та же»** → формы вхождения дописываются в forms записи (опечатка —
    та же сущность), jsonl обновляется;
  - **«новая»** → новый ULID, href этого вхождения переписывается в документе
    через `editor.replace` — только для открытой вкладки (закрытые файлы
    приложением не правятся), старый ULID живёт, пока есть другие вхождения;
  `removeMissing(root, ulid)` → строка удаляется из jsonl.
- **B-4. Панель** — секция **«Репо»** в дропдауне NER (документные секции
  ниже, T3-10): строка-статус «скан: N док., changed X · missing Y · known Z»,
  кнопка «Скан репо»; строки changed (значение → эталон, «Та же»/«Новая»),
  missing (тип·значение, «Вывести»), unknown-known (тип·значение·док,
  «Разметить» — bulk-редактом в конкретном документе, позиция из скана);
  кнопка «Пересобрать индекс» (B-3).
- **B-5. Инкремент + инвалидация**: инкремент при сохранении уже есть (T3-11);
  `useFileWatcher` при изменении `entities.jsonl` сбрасывает кэш
  `entitiesIndex` (новый `invalidateEntitiesIndex(path)`), чтобы внешний
  `make`/git не оставлял устаревший кэш — зеркально `harnessStore.invalidatePath`.
- **B-6. Диагностика из скана не пишет в документы**: скан — чтение + отчёт;
  записи в документы только явными действиями пользователя («Новая»,
  «Разметить») и только в открытых вкладках (dirty, сохранение за ним).
- **B-7. i18n ru/en**; фикстуры ULID — правдоподобные `01J…` (§16).

## 4. Проверки

1. **Скан**: 2 документа с разметкой (общий ULID, склонения) + один без →
   вхождения по ULID; fenced-код пропущен; скрытые/node_modules не обходятся.
2. **Diff**: правка текста ссылки → changed; ULID без вхождений → missing;
   неразмеченное совпадение с forms → unknown-known; совпадение внутри
   существующей разметки — не unknown.
3. **Решения**: «та же» → форма в forms, jsonl обновлён; «новая» → href в
   открытой вкладке переписан, jsonl не изменился; «Вывести» → строка удалена.
4. **Rebuild**: jsonl = сводка скана; canonical переживает пересборку.
5. **Watcher**: fs-change по entities.jsonl → кэш сброшен.
6. `pnpm test`, `npx tsc --noEmit`, `npx vite build`. GUI-приёмка — с
   пользователем (lm_hrdo_2).

## 5. Риски / ограничения

- Скан читает все .md репо: большие репо — секунды; кнопка ручная, кэш до
  следующего скана (автоскан не делаем).
- Дерево незагруженного корня — рекурсивный listDirectory; очень глубокие
  деревья ограничены глубиной 8.
- «Новая» для закрытой вкладки недоступна (нет записи в нередактируемые
  файлы) — тост-подсказка открыть документ.
- Конфликт типов ULID (T3-флаг) в панель не выводится — после приёмки, если
  понадобится.
- Позиции скана устаревают при правке — действия берут свежий контент
  вкладки и пересчитывают смещение (поиск значения в строке) перед replace.
