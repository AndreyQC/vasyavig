## Ключевые находки

1. **Флаг `u` в регулярке — не опция.** Без него `\p{L}` в не-unicode-режиме
   матчит литерал «p{L}», границы слова молча перестают работать («Иван»
   ловился внутри «Иванович»). Ловится только тестом.
2. **Текстовые runs вместо `textContent`.** У блока с inline-листами
   (hardbreak) `textContent` расходится с координатами PM. Матчинг идёт по
   непрерывным цепочкам текст-узлов без link-марок (`collectTextRuns`);
   смежные узлы с разными марками конкатенируются — форма через границу
   bold/italic узнаётся.
3. **«Голая» фамилия не склоняется** — шаблоны lvovich требуют инициалов или
   полного ФИО (`expandPerson` от «Иванов» даёт только саму форму; от
   «Иванов Иван Иванович» — 6 падежей × шаблоны). Не регрессия T3d, а её
   граница: подсветка «Иванова» появится, когда в записи есть полная форма.
4. **Матчинг регистрозависим** — согласованно с `matchEntityEntry`, меньше
   ложных срабатываний (в отличие от `aliasPattern` маскирования, который
   толерантен к дрейфу регистра).

## Известные ограничения / NOT done

- Подсветка **только WYSIWYG** — в Markup-режиме декорации не строятся (как у
  чипов).
- Пересборка декораций на каждую транзакцию с правкой — тот же бюджет, что у
  чипов; на больших документах, если станет заметно, — кэш по блокам (T6-6).
- Неоднозначность формы сейчас только цвет; список кандидатов и разрешение —
  панель конфликтов T6-5.
- «Создать отдельную» не предлагает связь (`works_at` и т.п.) — T6-5/T6-2.
- Подсветка не знает о Markdown-разметке вне PM (Markup-режим, превью) — для
  превью подсветка не планируется (это вид рендера, а не редактирования).
