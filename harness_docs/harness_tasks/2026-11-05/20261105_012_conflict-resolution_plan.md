## Цель

Одна и та же форма в справочнике у нескольких сущностей (однофамильцы,
одноимённые организации) — различать по контексту и связям; при конфликте —
дать пользователю выбор и **закрепить** решение якорем в документе.

## Движок разрешения

Вход: значение + позиция в документе + контекст.

1. **Якорь** (чип) в документе → точный ULID (разрешено, дальше не идём).
2. Единственное совпадение формы/алиаса → разрешено.
3. Несколько кандидатов → **контекст**:
   - контекст = Markdown-блок (абзац / строка таблицы / пункт списка),
     fallback — весь документ;
   - в контексте — другие известные сущности (организация, проект);
   - **явная связь** кандидата с сущностью контекста (`works_at`, `member_of`,
     `role_in`) → кандидат выигрывает;
   - иначе — максимум по **профилю co_occurs** в этом документе;
   - иначе — **конфликт** (требует решения пользователя).
4. Разрешено → бейдж типа (с уточнением «ООО Ромашка», если есть связь).

## Панель конфликтов

- Список конфликтов: форма, документы и позиции, кандидаты (canonical, тип,
  связи, где встречается).
- Действия по кандидату:
  - **«Это он»** → записать связь (вид выбирается: `works_at` / `member_of` /
    `role_in`) + поставить **якорь** в вхождения;
  - **«Это отдельная сущность»** → создать новую запись + связь + якорь;
  - **«Всегда связаны по форме»** → записать `alias_of` (объединить).
- Авто-режим (флаг в настройках): якоря ставятся сами там, где форма
  неоднозначна, но разрешение однозначно по связям.

## Якорь (чип) в документе

- Формат — существующий: `[текст](vas-entity:<type>:<ULID>)`.
- Вставка — через `editor.replace()` (паттерн `restoreUrls`), работает в обоих
  режимах.
- При вставке: тип берётся из разрешения, ULID — из кандидата.
- Если вхождение уже размечено — якорь не дублируется.

## Риски

1. **Тихая подмена сущности** при неверной связи → связи из UI явные и
   отменяемые; `co_occurs` — только предложения; неоднозначные формы
   подсвечиваются как неоднозначные.
2. Хрупкость контекста (абзац изменили) → якорь фиксирует решение.
3. Разбор Markdown-блоков — эвристика (заголовок/абзац/таблица); при сбое
   fallback на документ.
4. Авто-якоря меняют документы без спроса → авто-режим выключен по умолчанию.
