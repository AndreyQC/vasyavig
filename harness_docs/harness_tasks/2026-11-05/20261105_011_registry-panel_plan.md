## Цель

Дать одно место, где справочник правится: сущности, формы, алиасы, типы,
связи, слияние дублей.

## Почему отдельная панель, а не секция ассистента

- Справочник — **per-harness-root** (репозиторий), панель ассистента — per-документ.
- Управление справочником — не про текущий документ, а про репозиторий.
- Место: **левая панель** (как панель графа Phase 7) или отдельный экран.

## Состав

### Список сущностей

| Что | Как |
|---|---|
| Фильтр по типу | сегменты (все / person / org / loc / email / …) |
| Поиск | по canonical и формам |
| Строка | тип-бейдж · canonical · кол-во форм · кол-во документов |
| Действия | изменить canonical, формы/алиасы, тип, удалить, показать связи |

### Форма сущности (редактор)

- `canonical` — текстовое поле.
- `forms` — наблюдаемые (readonly, из документов; помечаются источником).
- `aliases` — ручные: список с добавлением/удалением; сюда же кросс-языковые
  формы («John Smith»).
- Тип — из справочника типов (`entityTypes.ts` + `harness.yaml`).

### Вкладка «Связи»

- Рёбра сущности: `works_at`, `member_of`, `role_in`, `alias_of`.
- Явные (`explicit`) — добавить/убрать вручную; выведенные (`co_occurs`) —
  показаны отдельно, read-only, с числом совместных появлений и списком
  документов.
- Добавление связи: выбрать целевую сущность + вид связи.

### Слияние дублей

- Дубль = несколько ULID с пересекающимися формами.
- Слияние: выбрать «главную» запись; остальные — в неё (формы + связи +
  алиасы); удалить остальные ULID из индекса; **поправить якоря** в документах
  (замена `vas-entity:<type>:<old>` → `<type>:<main>`) — там же, где это уже
  делается для конфликтов типов (`entityScanStore.resolveTypeConflict`).

## Хранилище

- Новый стор `entitiesIndexStore` (zustand):
  - `entries: EntityIndexEntry[]`, `relations: EntityRelation[]`, `path`,
  - `reload(dir)`, `upsert(entry)`, `remove(ulid)`, `merge(from, into)`,
    `setAliases(ulid, aliases)`, `addRelation(rel)`, `removeRelation(rel)`.
- Запись — в `entities.jsonl` / `relations.jsonl` через функции T6-1;
  после записи — обновление состояния без перечитывания файла.
