## 1. Цель и границы

**Цель.** Панель навигации по реестру документов: из открытого документа видны
и открываются все его связи (`based_on` — основания, `related` — связанные,
порождённые — документы, созданные на основе него), плюс обзорное дерево
репозитория с фильтрами по `project`/`type`.

**Не входит:** графовая БД (источник — реестр, см. D2), редактирование связей,
переход к якорю (`#<anchor>` — отдельная задача, Phase 8), автодополнение
ULID-ссылок.

**Что уже есть и не переделывается:** кнопка «Связи» в тулбаре
(`HarnessLinksButton`) — поповер со связями *конверта текущего файла*;
плашечка `HarnessUlidPopover`; дашборд задач (`TaskDashboard`). Задача 5
добавляет навигацию по *реестру* (включая обратные связи), а не дублирует
поповер.

## 3. Решения

**D1 — модель графа = чистая функция от записей реестра.** Новый модуль
`src/lib/harnessGraph.ts`: `buildDocumentGraph(entries)` -> узлы (по ULID),
обратный индекс `childrenByParent` (порождённые), симметричная смежность
`related` (D6), обратный `parentsByChild`. Никакого I/O в модуле — вход это
массив записей реестра.

**D2 — источник данных переиспользуемый, а не новый.** Реестр уже загружен в
`harnessStore.indexes` (по корню репо) и обновляется watcher'ом. Граф — чистая
производная от `indexes[repoRoot]`, пересчитывается по `harnessStore.version`.
Когда реестр переедет в БД (позже), меняется только источник записей; граф и
UI не трогаем — тот же принцип, что у `TaskSource` в задаче 6.

**D3 — порождённые документы = обратный `based_on`.** Направление
`based_on` одностороннее: `A.based_on = [B]` -> B — основание, A — порождённый.
Обратное ребро выводится индексом `childrenByParent`.

**D4 — `related` трактуем симметрично** (см. Q3): если A указывает на B, то B
тоже видит A в разделе «Связанные» (в реестре `related` уже симметричен по
факту — 691 ребро, все в одну сторону записаны, но пары взаимны).

**D5 — два представления в одной панели.** «Вокруг документа» (по активной
вкладке: основания / порождённые / связанные — то, что просит roadmap в
проверке) и «Обзор» (дерево по типам с фильтрами `project`/`type`).

**D6 — переход по узлу = открытие вкладкой.** Клик по узлу открывает документ
существующим путём `openFile` (как дашборд), плюс переход к `#<anchor>` — когда
появится поддержка якорей (Phase 8).

**D7 — узел графа = запись реестра** (`ulid`, `path`, `title`, `type`,
`project`, `created`, `updated`, `related`, `based_on`). Заголовок — `title`,
fallback — имя файла.

**D8 — фильтры обзора:** `project` (в примере один — `lm_hrdo_2`), `type`
(15 значений), плюс текстовый поиск по title/path. Фильтры влияют на список
дерева, не на граф вокруг документа.

**D9 — переиспользование UI-кита:** `Select` (фильтры), `TextInput` (поиск),
`Text`, `Icon`; стили — рядом с дашбордом в `Sidebar.css`.

**D10 — место панели:** третий режим сайдбара `tree | tasks | graph` (см. Q1),
переключатель — рядом с кнопкой «Задачи» в `SidebarHeader`.
