## 2. Решения

### 2.1. Формат ссылки — вариант C

```markdown
[20261027_001_ulid_body_links_plan.md](ulid:01M43R3ZGSNXQ0KSMZ9JSZEZ5W)
```

- Видимый текст — имя файла-цели; `href` — `ulid:<ULID>`.
- Ссылка на место в документе: `[имя](ulid:<docULID>#<anchorULID>)`.
- Никаких других полей в тексте: метаданные берутся из реестра по ULID (U1).

**Почему C, а не A/B/D/E/F.**

| Вариант | Вердикт | Причина |
|---|---|---|
| A. голый ULID | только backward compat | не выглядит ссылкой, нет имени файла, клик по всему тексту |
| B. `` `ULID` `` | нет | то же, плюс код-стиль в тексте |
| C. `[имя](ulid:…)` | **принят** | обычный markdown, round-trip byte-exact, имя видно, ULID машинно-читаем |
| D. `[имя](<ULID>)` | нет | ULID выглядит относительным путём: «битая» ссылка вне приложения и риск ложного резолва |
| E. YFM-спецсинтаксис | нет | нет поддержки в установленных версиях, не нужен |
| F. метаданные в `title` | отвергнут (U1) | дублирование устаревает; реестр — источник правды |

### 2.2. Метаданные не дублируются (U1)

`title`/`type`/`project`/путь/даты/связи в тексте не хранятся. Имя файла —
единственный «снимок» в тексте (нужен для читаемости plain markdown);
актуальные данные приложение берёт из `documents.jsonl` по ULID.

### 2.3. Кликабельность только внутри Vasyavig (U2)

Схема `ulid:` вне приложения неизвестна: GitHub/Gramax покажут текст без
перехода. Это принято; относительные пути в href не вводим (они ломаются при
переносе документа, ULID — нет).

### 2.4. Плашечка при наведении (U3)

Видимый текст — имя файла; hover — popover с полями реестра: `title`, `type`,
`project`, путь от корня, `created`/`updated`, `related`/`based_on`, действия
«Открыть»/«Связи». Нативный `title` не подходит (задержка ОС, нет кнопок).

### 2.5. Якоря внутри документа (U4, Q9) — концепция

- Маркер места со своим ULID и типом `anchor`; рекомендация — скрытый
  конверт-комментарий (как harness-yaml) + видимый view-only бейдж в редакторе.
- Ссылка: `ulid:<docULID>#<anchorULID>`.
- Переход: открыть документ, найти маркер по ULID, проскроллить к следующему
  блоку и подсветить; реестр не требуется.
- Реализация — отдельная задача (кандидат Phase 8), в текущую не входит.

## 3. Прототип: результаты

Фикстура: ссылки в параграфе, YFM-note и YFM-таблице; редактор собран как
`YfmSpecsPreset` + `FullSpecsPreset`.

| Проверка | Результат |
|---|---|
| WYSIWYG/YFM parse -> serialize (`getValue`) | ссылки сохраняются дословно, включая `#<anchor>`; повторный проход идемпотентен |
| Ссылки внутри note и таблицы | сохраняются; таблица сериализуется блоками — известное ограничение, не связано с задачей |
| `@diplodoc/transform` по умолчанию | **href вырезается**: `<a>файл</a>` (`sanitize-html`, `allowedSchemes`) |
| transform + `sanitizeOptions.allowedSchemes` с `ulid` | `href="ulid:…"` сохраняется |
| DOMPurify с текущим `ASSET_SAFE_URI_RE` | href вырезается |
| DOMPurify + `ulid` в `ALLOWED_URI_REGEXP` | href сохраняется |

**Вывод.** Формат C подтверждён на уровне редактора. Для превью обязательны
две правки конфигурации (обе — в `src/components/EditorArea/SplitPreview.tsx`):
`sanitizeOptions.allowedSchemes` в `transform` (строка 70) и `ulid` в
`ALLOWED_URI_REGEXP` (строка 33). Без них ссылка рендерится текстом.
