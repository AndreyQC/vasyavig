## 1. Причина

Схема `ulid:` слишком общая: по grep `](ulid:` легко спутать с другими
идентификаторами/текстом, а слово `ulid` встречается в конвертах, закладках и
`related`/`based_on`. Нужен однозначный маркер, по которому поиск сразу
отличает ссылку от прочих упоминаний.

## 2. Решение

- **Пишем:** `[<имя файла>](harness_ulid:<ULID>)`,
  якорь — `harness_ulid:<docULID>#<anchorULID>`.
- **Читаем:** legacy `ulid:` остаётся валидным (обратная совместимость);
  миграция существующих документов не нужна. `buildUlidHref` всегда пишет
  новую схему.
- Поиск: `harness_ulid:` — ровно один токен, не пересекается с конвертами
  (`id: 01…`), закладкой (`` `01…` ``) и списками связей.

## 3. Прототип (2026-10-27)

Проверены `ulid:`, `harness_ulid:`, `harness-ulid:`, `vasyavig:` на трёх слоях:

| Слой | `harness_ulid:` |
|---|---|
| `@diplodoc/transform` | href сохраняется (в т.ч. без `allowedSchemes`) |
| DOMPurify | href сохраняется |
| Gravity WYSIWYG parse -> serialize | ссылка и якорь сохраняются дословно |

**Важная находка.** Подчёркивание не входит в URI-схему по RFC 3986
(`ALPHA *( ALPHA / DIGIT / "+" / "-" / "." )`). Поэтому `sanitize-html` не
распознаёт `harness_ulid` как схему и пропускает href как относительный путь;
DOMPurify — по fallback-ветке регекспа (не как явную схему). Практические
следствия:

- в приложении это безопасно: href всё равно снимается после разбора
  (`data-ulid`), наружу ссылка не уходит;
- `allowedSchemes`/`ALLOWED_URI_REGEXP` для `harness_ulid` — страховка и
  задел на ужесточение санитайзера, реально они нужны для legacy `ulid:`;
- вне Vasyavig такая ссылка не обязана быть кликабельной (U2), но текст
  остаётся читаемым.

Альтернатива `harness-ulid:` (валидная схема) работает так же, но требует
явного allow-list; выбран вариант пользователя — слитный `harness_ulid:`.

## 6. Ограничения

- `harness_ulid:` — не валидная URI-схема по RFC; в браузере/GitHub ссылка не
  будет кликабельной. Для Vasyavig это не важно (U2).
- Legacy `ulid:` поддерживается бессрочно на чтение; новых ссылок с ним
  приложение не создаёт.
- Автодополнение/вставка по-прежнему вне объёма (отдельная задача).
