## 1. Контекст проблемы (установлено исследованием)

Редактор открывает markdown всегда в WYSIWYG (`MarkdownEditor.tsx: initial mode: "wysiwyg"`).
markdown-it (токенайзер Gravity-редактора) при парсинге применяет `normalizeLink` —
кириллица в URL кодируется в %-вид: `#1-введение` -> `#1-%D0%B2%D0%B2%D0%B5%D0%B4%D0%B5%D0%BD%D0%B8%D0%B5`.
Сериализатор записывает href как есть. Последствия:

- переключение WYSIWYG -> Markup подменяет текст сериализованной версией (закодированные URL);
- событие `change` срабатывает уже при переключении (`replace()` в CodeMirror = транзакция
  с `docChanged`) — вкладка становится dirty без правок;
- Ctrl+S записывает перекодированные якоря на диск.

У Gravity-редактора есть публичное API расширений `builder.configureMd(cb)`, позволяющее
переопределить функции markdown-it — это и есть точка фикса.

## 2. Цели фазы

1. Открытие/правка/сохранение markdown в Vasyavig не кодирует не-ASCII в URL.
2. Кнопка «Восстановить кириллицу в ссылках»: декодирует %-кодирование в URL существующего
   файла (якоря, пути картинок) — лечит файлы, уже побитые конвертацией/редактированием.
3. Кнопка «Составить оглавление»: генерирует TOC из заголовков документа, якоря совместимы
   с превью (`@diplodoc/transform`).

## 3. Решения (проработка)

### 3.1 Фикс перекодирования — `preserveUrlsExtension`

Новый файл `src/lib/preserveUrlsExtension.ts` (паттерн — как `spellcheckExtension.ts`):

```ts
import type {Extension} from "@gravity-ui/markdown-editor";

export function preserveUrlsExtension(): Extension {
  return (builder) => {
    builder.configureMd((md) => {
      md.normalizeLink = (url) => url;       // без %-кодирования не-ASCII
      md.normalizeLinkText = (url) => url;
      return md;
    });
  };
}
```

- Подключение: `MarkdownEditor.tsx` -> `wysiwygConfig: {extensions: [spellcheckExtension(), preserveUrlsExtension()]}`.
- `configureMd` без параметров применяется к обоим токенайзерам (markup и text) — то, что нужно.
- `validateLink` остаётся штатным — защита от `javascript:` и пр. не меняется.
- Фикс **не декодирует** уже закодированные ссылки в существующих файлах — для этого 3.2.
- Ограничение (принять осознанно): сериализация Gravity в целом не байт-в-байт равна
  исходному markup (прочие нормализации форматирования). Переключение режимов всё равно
  заменяет текст сериализованной версией; фикс убирает именно %-кодирование URL.
  Степень прочих расхождений проверить на реальном файле (см. §6).

### 3.2 Кнопка «Восстановить кириллицу в ссылках»

Новый файл `src/lib/restoreCyrillicUrls.ts`:

```ts
export function restoreCyrillicUrls(md: string): {text: string; changed: number};
```

- Регекс по destination inline-ссылок и картинок (`[t](url "title")`, `![](url)`, `<url>`):
  находим URL, прогоняем через безопасный декодер.
- Декодер: только %-последовательности, дающие не-ASCII (кириллица и другой UTF-8 > 0x7F).
  `%20`, `%28` и прочие ASCII-коды **не трогаем** — декодированный пробел/скобка разорвут
  markdown-ссылку. Невалидные последовательности (`%D0` без пары, битый UTF-8) — пропуск.
- Текст вне URL не изменяется вообще.
- Применение: `restoreCyrillicUrls(content)` -> если `changed > 0` -> `editor.replace(text)`
  -> событие `change` -> store `updateContent` -> вкладка dirty. Сохранение — за пользователем.

Доступ к instance редактора снаружи `MarkdownEditor.tsx` (кнопка живёт в app-уровне):

- Новый реестр `src/lib/editorRegistry.ts`: `Map<path, editorInstance>`; `MarkdownEditor.tsx`
  регистрирует в `useEffect` (mount/unmount). Кнопки берут редактор активной вкладки.
- Альтернатива (отвергнута): менять `content` в store напрямую — редактор читает
  `initial` только при монтировании, внешнюю замену не подхватит.

Undo: в markup-режиме `replace()` — обычная CM-транзакция (undoable). В WYSIWYG `replace()`
пересоздаёт документ — история undo сбрасывается. Принять как ограничение; кнопка —
редкая операция над всем файлом.

### 3.3 Кнопка «Составить оглавление» (TOC)

Новый файл `src/lib/generateToc.ts`:

```ts
export function generateToc(md: string, opts: {minLevel: number; maxLevel: number}): {
  toc: string;      // готовый markdown-список
  replace: {from: number; to: number} | null; // диапазон существующего блока TOC
};
```

- Парсинг заголовков — markdown-it (те же токены, что видит редактор). `markdown-it`
  добавить прямыми зависимостями проекта (`markdown-it@13`, совпадает с версией редактора;
  сейчас он в `node_modules` транзитивно).
- Текст заголовка — конкатенация text-токенов inline (без разметки), как в файлах пользователя.
- Якоря — GitHub-стиль, как в превью: проверить, какой slugger использует `@diplodoc/transform`
  (ожидаемо `github-slugger`: lowercase, пунктуация удаляется, кириллица сохраняется,
  пробелы -> `-`); подключить тот же пакет и сверить тестом на реальном файле
  (`1. Введение` -> `#1-введение`). Несовпадение слагов = TOC не кликается в превью,
  поэтому сверка обязательна.
- Формат списка — как в файлах пользователя: `- [Заголовок](#якорь)`, вложенность —
  2 пробела на уровень.
- Вставка через `editor.replace()` (той же механикой, что 3.2).

## 5. USER_INPUT — вопросы к пользователю

**USER_INPUT #1 — уровни заголовков в TOC.**
Варианты: (a) H1–H4 все; (b) только H2–H3 (компактно); (c) диалог с выбором при нажатии.
Рекомендация ИИ: **(a) H1–H4** — документы пользователя содержат и H1-разделы, и глубокую
вложенность (3.2.01); выкидывать уровни в «маленькой фазе» не стоит, фильтрацию можно
добавить позже.

**USER_INPUT #2 — существующий блок оглавления.**
Варианты: (a) найти заголовок «Оглавление»/«Contents» (H1–H2) и заменить блок под ним
до следующего заголовка того же уровня; (b) всегда вставлять новый TOC в начало, старый
оставить; (c) модалка «заменить/вставить».
Рекомендация ИИ: **(a)** — «перегенерация» естественна для повторных нажатий; вариант (c)
добавляет экранную работу без явной потребности.

**USER_INPUT #3 — размещение кнопок.**
Варианты: (a) своя панель кнопок в app-уровне над областью редактора (в `EditorArea`),
видна в обоих режимах; (b) интеграция в тулбар Gravity через actions API расширений;
(c) контекстное меню вкладки.
Рекомендация ИИ: **(a)** — просто, предсказуемо, одинаково для WYSIWYG/Markup/Split;
(b) дороже (иконки, порядок в тулбаре, поведение в markup-режиме) — можно сделать позже.

Горячие клавиши: по умолчанию **не добавляем** (комментарий в final, если пользователь
не скажет иное).
