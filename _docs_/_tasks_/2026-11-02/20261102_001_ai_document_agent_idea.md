## 1. Идея в одном абзаце

Встроить в Vasyavig ассистента, который помогает работать с markdown и
конвертированными документами: находит проблемы (устаревшие ссылки, битые
якоря, устаревшее оглавление, пропуски harness-конверта), предлагает правки
диффом и выполняет узкие операции (например, markdown -> HTML-письмо).
Ассистент двухуровневый: быстрый локальный агент с маленькой моделью и жёстко
ограниченным набором инструментов, и эскалация к сильному агенту (OpenCode
server / ACP, OpenAI-совместимый API), когда локальной модели не хватает.
Ключевой принцип: **агент не получает файловую систему и shell; он получает
типизированные возможности приложения, а любые изменения проходят через
предложение (diff) и подтверждение пользователя.**

## 2. Зачем это нужно

Уже сейчас в приложении есть ручные инструменты, которые просят «понимания
контекста»:

- «Восстановить ссылки» чинит %-кириллицу и `\_`-escape, но не решает, где
  ссылку лучше заменить на `harness-ulid:` и как назвать документ.
- «Оглавление» генерируется механически; непонятно, когда его надо обновить.
- В harness-репозиториях есть реестр, граф и task-yaml, но нет помощника,
  который скажет «этот документ — сирота», «здесь `based_on` не заполнен»,
  «после переименования остались относительные ссылки».
- Конвертация anydoc даёт markdown, но дальше документ надо доводить руками.
- Нет быстрого способа сделать из заметки письмо, тезисы, задачу или
  выжимку для другого человека.

Ассистент не заменяет существующие кнопки, а **оркестрирует их**: сначала
детерминированные проверки, затем модель — только там, где нужно понимание
текста. Это дешевле, предсказуемее и тестируемее, чем «чат, который умеет
всё».

## 3. Принципы

1. **Local-first.** По умолчанию всё работает с локальной моделью; наружу
   ничего не уходит без явного согласия. Офлайн-режим — полноценный.
2. **Proposals-only.** Быстрый агент не пишет файлы и не сохраняет их. Он
   возвращает предложение правки; применяет его приложение после
   подтверждения, через существующий `editor.replace()` — с dirty-флагом и
   undo.
3. **Tools, not FS.** Вместо `read_file(path)` / `shell` — логические
   инструменты: «активный документ», «выделение», «документ по ULID»,
   «соседи по графу», «задачи с фильтром». Пути и права резолвит приложение.
4. **Recipes first, autonomy later.** Сначала — сценарии с одним-двумя
   вызовами модели и строгим JSON-ответом. Свободный tool-loop — после того,
   как локальная модель докажет надёжность.
5. **Escalation, not replacement.** Сильный агент вызывается осознанно, с
   «контекст-паком» (что именно отправляем), и по умолчанию в режиме
   советника: вернуть патч, не трогать файлы.
6. **Всё видно.** Пользователь видит, какие инструменты вызваны, что уйдёт
   наружу, сколько это стоит, и может отменить в любой момент.

## 4. Архитектура

```
┌──────────────────────────── Vasyavig ─────────────────────────────┐
│ UI: панель «Ассистент» (справа, сворачиваемая)                     │
│  chips контекста | quick actions | чат | предложения (diff)        │
├────────────────────────────────────────────────────────────────────┤
│ agentStore (session, настройки, история запусков)                  │
│   │                                                                │
│   ├─ recipes/  (review-links, toc, email, summary, draft, …)       │
│   │     └─ context builder ──┐                                     │
│   ├─ tool executor (policy) ─┼─ editorStore / fileStore            │
│   │                          ├─ harnessStore / harnessGraph        │
│   │                          └─ lib: restoreCyrillicUrls, TOC, …   │
│   │                                                                │
│   └─ providers/                                                    │
│        ├─ local OpenAI-compatible (Ollama / LM Studio / llama.cpp) │
│        ├─ OpenCode server  (advisor: контекст -> патч)             │
│        └─ OpenCode ACP     (operator: permissions -> approvals)    │
├────────────────────────────────────────────────────────────────────┤
│ Rust: agent_service — HTTP/SSE-прокси, таймауты, отмена, лимиты   │
│       keyring — ключи API; commands — agent_chat/cancel/probe      │
└────────────────────────────────────────────────────────────────────┘
```

Почему HTTP-прокси в Rust, а не `fetch` из webview: CORS у локальных
серверов (Ollama/OpenCode) настраивается отдельно, origin Tauri на Windows
(`http://tauri.localhost`) не всегда в allowlist; ключи API не должны жить в
localStorage; отмену и лимиты проще держать в одном месте. Зависимость —
`reqwest` с `default-tls` (schannel), без `ring`/`aws-lc`, чтобы не добавлять
C-сборку: release-сборка на машине разработчика блокируется антивирусом
(см. чекпоинт 20261028_003, «Среда»).

## 5. Два уровня агента

### 5.1 Быстрый агент (локальная модель)

- Небольшая instruct-модель класса 4–8B с хорошим JSON/instruction-following,
  запущенная в Ollama / LM Studio / llama-server / vLLM. Модель не
  бандлится в приложение: пользователь указывает base URL и имя модели,
  настройки проверяются кнопкой «Проверить подключение».
- Контекст: активный документ или выделение, результаты детерминированных
  проверок, ближайшие соседи по графу. Полный документ — только в пределах
  лимита, с чанкованием по заголовкам.
- Возможности: читать (через tools), проверять, объяснять, предлагать
  правки, генерировать текст (саммари, письмо, перевод, черновик), вызывать
  детерминированные инструменты.
- Ограничения: максимум шагов (6), таймаут (60 с), лимит токенов, отмена;
  нет записи, нет shell, нет сети, кроме endpoint провайдера.

### 5.2 Сильный агент (эскалация)

Два режима, оба включаются явно:

| Режим | Что делает | Безопасность |
|---|---|---|
| **Advisor** (по умолчанию) | Получает контекст-пак и возвращает предложение/патч; не имеет доступа к файлам | Ничего не уходит, пока пользователь не увидит превью отправки; вернувшийся патч проходит тот же diff-approval |
| **Operator** (opt-in) | Полноценный агент с инструментами: OpenCode ACP (`opencode acp`, JSON-RPC over stdio) или сервер; может читать/писать файлы и запускать команды в пределах workspace | Каждый tool-call идёт через permission-запрос приложения: allow once / allow for session / deny; shell и запись — с показом команды/диффа; audit log; kill switch |

Провайдеры эскалации:

1. **OpenAI-совместимый API** — проще всего: тот же адаптер, что у локальной
   модели; подходит для сильной локальной модели или внешнего API.
2. **OpenCode server** — `opencode serve --port 4096`: REST + SSE,
   `POST /session/:id/message`, события `GET /event`, OpenAPI по `GET /doc`;
   Basic Auth через `OPENCODE_SERVER_PASSWORD`. Хорош для advisor-режима.
3. **OpenCode ACP** — `opencode acp`: JSON-RPC 2.0 over stdio, handshake
   `initialize` -> `session/new` -> `session/prompt`, streaming
   `session/update`, `session/cancel`. Это родной протокол «редактор —
   агент», и permission-запросы ложатся в UI приложения. Кандидат для
   operator-режима.

**Контекст-пак** — версионированный JSON, который собирает приложение, а не
модель:

```json
{
  "schemaVersion": 1,
  "goal": "проверить ссылки и обновить оглавление",
  "instructions": "верни только proposals по схеме",
  "workspace": {"rootId": "w1", "kind": "harness"},
  "activeDocument": {"ulid": "...", "path": "docs/plan.md", "content": "..."},
  "selection": {"from": 120, "to": 480, "text": "..."},
  "findings": [{"rule": "legacy-link", "line": 14, "detail": "..."}],
  "graph": [{"ulid": "...", "title": "...", "relation": "related"}],
  "constraints": {"maxProposals": 10, "output": "proposal-json-v1"},
  "redactions": ["api-key"]
}
```

Перед отправкой показывается превью: какие документы, сколько символов,
какие секреты вырезаны. Для внешнего провайдера — отдельное подтверждение и
оценка стоимости.

## 6. Инструменты (tool surface)

Модель не получает пути и команды. Аргументы — логические идентификаторы;
приложение само резолвит их в файлы в пределах открытых корней.

| Tool | Тир | Что делает | Лимиты |
|---|---|---|---|
| `get_active_document` | read | Текст, путь, режим, ULID активной вкладки | размер документа |
| `get_selection` | read | Выделение и позиция курсора | — |
| `list_open_documents` | read | Открытые вкладки и dirty-флаги | 50 |
| `get_document` | read | Документ по ULID из реестра harness | только реестр |
| `search_documents` | read | Поиск по workspace (лексический) | 20 результатов, 200 символов на фрагмент |
| `get_related_documents` | read | Соседи по графу (`based_on`, `related`) | 50 |
| `list_tasks` | read | Задачи task-yaml с фильтрами | 100 |
| `check_document` | pure | Детерминированные проверки: ссылки, якоря, TOC, конверт | — |
| `render_email_html` | pure | Markdown -> HTML-письмо (санитизация + inline CSS) | размер, вложения |
| `propose_edit` | propose | Предложение правки (diff + rationale), без записи | max 10 на запуск |
| `apply_proposal` | write | Вызывается **приложением** после подтверждения, не моделью | — |

Чего в наборе принципиально нет: `read_file(path)`, `write_file`,
`list_dir`, `run_shell`, `open_url`, `http_request`. Это не «запрещено
промптом» — таких инструментов просто нет в реестре для быстрого тира.

Политика исполнения — в коде, не в системном промпте:

```ts
type Tier = "read" | "propose" | "write";
executeTool(provider, call) {
  assertToolAllowed(provider.tier, call.name);   // allowlist по тиру
  assertArgsShape(call.name, call.args);         // строгая схема
  assertBudget(provider.session);                // шаги, токены, время
  return TOOLS[call.name](resolveLogicalIds(call.args));
}
```

## 7. Безопасность

| Угроза | Механизм |
|---|---|
| Prompt injection в документе («удали все файлы») | Инструментов с побочными эффектами у быстрого агента нет; запись только через proposal + подтверждение; содержимое документа помечается как данные |
| Модель галлюцинирует правку | Diff с `original`/`replacement`; проверка, что `original` встречается ровно один раз; hash документа против устаревшей правки; undo; никакого автосохранения |
| Выход за пределы workspace | Логические ID вместо путей; резолв только внутри открытых корней; канонизация, запрет `..` и symlink-выходов |
| Утечка секретов наружу | Редакция (`sk-…`, токены, `.env`-паттерны) до сборки контекст-пака; превью отправки; внешний провайдер — только с явным согласием |
| Вредоносный/подменённый endpoint | Локальный быстрый агент — только localhost; внешний — HTTPS; ключи в keyring; проверка модели и endpoint в настройках |
| Неограниченный расход | Бюджет шагов/токенов/времени, отмена, оценка стоимости для внешнего провайдера |
| Оператор натворил дел | Отдельный opt-in, permission-запрос на каждый tool-call, shell с показом команды, audit log, рекомендация git-коммита перед сессией |

Дополнительно: не читать `.git/`, `.env`, ключи, бинарники и файлы вне
корней; ограничивать размер контекста; не логировать содержимое документов
по умолчанию (только хэши и метаданные).

## 8. UX

- **Панель справа**, ресайзится, Ctrl+Shift+A; не воровает фокус. На узком
  окне — оверлей. Полноценная вкладка «чат» — позже, если панели мало.
- **Контекст-чипы:** активный документ, выделение, закреплённые документы,
  harness-репозиторий; всё можно снять.
- **Quick actions** зависят от состояния документа: «Найдено 3 устаревшие
  ссылки — исправить?», «Оглавление устарело — обновить», «Сделать письмо»,
  «Саммари», «Перевести», «Проверить документ».
- **Thread:** сообщения, карточки tool-call (сворачиваемые), статус
  «думает/читает/проверяет», кнопка «Стоп».
- **Proposal card:** diff, объяснение, «Применить», «Отклонить», «Показать в
  редакторе». Для нескольких правок — «Применить все».
- **Escalation card:** причина, состав контекст-пака, выбор провайдера,
  предупреждение о стоимости/утечке, кнопка «Отправить».
- **Настройки:** провайдер (URL, модель, ключ), «Проверить», лимиты,
  авто-подсказки on/off, офлайн-режим, audit log.
- **Статус-бар:** индикатор модели (не настроена / готова / занята), клик
  открывает панель.

## 9. Сценарии

| Сценарий | Что делает ассистент | На что опирается в коде |
|---|---|---|
| Гигиена документа | Находит legacy-ссылки (`%`-кириллица, `\_`, голые ULID, `harness_ulid:`), битые якоря, устаревший TOC, проблемы конверта; предлагает правки по одной | `restoreCyrillicUrls`, `anchorMatcher`, `generateToc`, `harnessEnvelope`, `harnessUlidLink` |
| Markdown -> письмо | Детерминированно рендерит HTML-письмо (inline CSS, 600px, картинки), модель пишет тему и preheader; экспорт `.html`/`.eml`/rich clipboard | `@diplodoc/transform`, DOMPurify, `HtmlViewer`, `emlParser` (для обратной операции) |
| Harness-навигация | «Где это описано?», «Кто основан на этом документе?», «Найди сирот», «Предложи `related`/`based_on`» | `harnessStore`, `harnessGraph`, `harnessIndex` |
| Черновик harness-документа | Предлагает конверт, ULID, скелет и запись в `documents.jsonl` (как proposal; запись — после task 7 write-path) | `harnessEnvelope`, Phase 7 задача 7 |
| Разбор офисного документа | После anydoc: выжимка, action items, чистка заголовков и таблиц, письмо из документа | `vendor/anydoc`, конвертер |
| Редактура | Переписать выделение (короче/формальнее/перевод), проверить термины по глоссарию, подсказать alt-текст | `harness_manifest.json`, spellcheck |
| Дашборд задач | «Что у меня в работе?» -> фильтр + сводка, переход к документу | `harnessTasks`, `TaskDashboard` |
| Пакетная миграция | Пройти по репозиторию, найти старые ссылки, собрать отчёт и пачку proposals | реестр + graph + batch-run (позже) |

Флагманский сценарий для демо — «Навести порядок в документе»: одна кнопка,
детерминированные проверки, объяснение каждого пункта и пачка diff'ов.
Он честно показывает, что агент не «магия», а ускоритель уже существующих
инструментов.

## 10. Почему recipes, а не автономный ReAct-цикл

Маленькие локальные модели плохо держат многошаговый tool-calling: путают
схемы, зацикливаются, «забывают» ограничения. Поэтому MVP строится на
**рецептах** — фиксированных пайплайнах:

1. Детерминированный шаг собирает факты (findings, граф, контекст).
2. Один вызов модели с жёсткой JSON-схемой (при поддержке — JSON mode /
   GBNF-грамматика).
3. Валидация ответа; при ошибке — один дешёвый retry с сообщением об ошибке.
4. Ответ превращается в proposals; применение — через UI.

Свободный чат с read-only инструментами — следующий этап, когда будет
понятно, что модель стабильно вызывает 3–5 инструментов. Это снижает риск и
даёт тестируемость: рецепт с mock-провайдером проверяется юнит-тестами.

## 11. Этапы (предложение)

| Этап | Объём | Содержание | Результат |
|---|---|---|---|
| 0. Каркас без AI | S | `emailHtml.ts` + панель с findings-списком и diff-модалкой; тесты | Работает «Письмо HTML» и «Проверить документ» без модели |
| 1. Локальный агент | M | Rust-прокси, OpenAI-совместимый провайдер, настройки, рецепт review-links/TOC, proposals | Локальная модель предлагает правки по кнопке |
| 2. Чат и контекст | M | Thread, контекст-чипы, read-only tools, стриминг, отмена, audit | Свободный чат по документу и workspace |
| 3. Эскалация-advisor | M | Контекст-пак, превью отправки, OpenCode server/OpenAI-совместимый адаптер, возврат патча | Сложную задачу можно отдать сильной модели |
| 4. Эскалация-operator | L | ACP-клиент, permission-UI, shell/file approvals, audit, kill switch | Сильный агент реально работает в workspace под контролем |
| 5. Позже | L | Эмбеддинги/семантический поиск, batch-миграция, write-path интеграция | Навигация и массовые операции |

Порядок 0 -> 1 -> 2 -> 3 выбран так, чтобы каждый этап был полезен сам по
себе и не требовал операторского доступа. Этап 4 — только после того, как
Phase 7 задача 7 (write-path) закрыта и понятна модель записи.

| Ссылки/якоря/TOC | `restoreCyrillicUrls`, `anchorMatcher`, `generateToc` | Детерминированные проверки и фиксы |

| Rust-команды | `src-tauri/src/commands/*`, `services/*` | Новый `agent_service` рядом |

## 13. Не-цели v1

- Автономная правка нескольких файлов без подтверждения.
- Shell, git-команды, сеть и браузер у быстрого агента.
- Автосохранение результатов работы агента.
- Бандлинг модели в установщик (тяжёлая упаковка, GPU-варианты, лицензии).
- Полноценный «чат обо всём» и RAG по всей файловой системе.
- Замена spellcheck/линтеров: ассистент их вызывает, а не переписывает.
- Собственный MCP-сервер/ACP-клиент в первом MVP (кандидаты на этап 4+).

## 14. Открытые вопросы (решения к принятию)

1. **Модель и железо.** Ориентир — 4–8B на CPU/одной GPU; нужно ли
   поддерживать совсем слабые машины (тогда только quick actions и
   эскалация)?
2. **Формат панели.** Правая панель (рекомендация) или отдельная вкладка,
   как в исходной идее `USER_IDEA.md`? Вкладка удобнее для длинного чата, но
   конкурирует с документами.
3. **Первый сценарий.** «Письмо HTML» (детерминированно, без модели) или
   «Проверить ссылки» (нужна модель)? Рекомендация: сначала письмо как
   каркас, затем ссылки.
4. **Эскалация.** Начинать с OpenCode server (HTTP/SSE) или сразу с ACP?
   Рекомендация: advisor через OpenAI-совместимый API, затем OpenCode
   server, ACP — для operator.
5. **Ключи и настройки.** keyring в Rust (рекомендация) или переменные
   окружения? Где хранить историю запусков и сколько?
6. **Применение правок в WYSIWYG.** Целиком заменять документ (как сейчас
   делают кнопки) или делать гранулярные transaction-правки? Первое проще,
   но возможен reformat при round-trip; второе дороже, но точнее.
7. **Письма и вложения.** Встраивать картинки base64 в `.html`, делать
   `.eml` с `multipart/related` или оставлять ссылки? Влияет на размер и
   совместимость клиентов.
8. **Фаза или внефазная серия.** Оформить как Phase 8 после Phase 7 задачи 7
   или как отдельные внефазные задачи (spike -> MVP)? Рекомендация: spike
   (этап 0) вне фазы, затем решить по результату.
9. **Приватность.** Нужен ли режим «не отправлять содержимое даже локальной
   модели» (только детерминированные проверки)? Стоит ли хранить audit с
   текстом proposals?
10. **Batch-операции.** Разрешать ли проход по всему репозиторию с пачкой
    proposals в v1 или отложить до этапа 5?

## 15. Риски

- **Качество локальной модели.** JSON-режим и рецепты снижают риск, но
  «умные» правки могут быть хуже, чем детерминированные. Поэтому
  quick actions и проверки должны работать без модели.
- **Round-trip WYSIWYG.** Применение markdown-патча к WYSIWYG может менять
  форматирование; нужны тесты на реальной схеме (у проекта уже есть
  `harnessRoundTrip*.test.ts`).
- **Эскалация затягивает.** OpenCode API/ACP развиваются; адаптер надо
  держать изолированным и версионировать контекст-пак.
- **Scope creep.** «Агент» легко превращается в платформу; не-цели v1 —
  обязательны.
- **Сборка.** Новые Rust-зависимости на машине с антивирусом: выбирать
  крейты без C-сборки; release-сборка и так недоступна (см. чекпоинт).
- **Доверие.** Любая ошибка агента на реальных документах бьёт по доверию;
  поэтому proposals, diff, undo и отсутствие автосохранения — не опции, а
  условие запуска.

## 16. Источники по эскалации

- OpenCode server: REST + SSE (`/session/:id/message`, `/event`, OpenAPI
  `/doc`, Basic Auth `OPENCODE_SERVER_PASSWORD`).
- OpenCode ACP: `opencode acp`, JSON-RPC 2.0 over stdio, `initialize` ->
  `session/new` -> `session/prompt`, streaming `session/update`,
  `session/cancel`, permission-запросы.
- ACP как протокол «редактор — агент»: подходит на роль operator-режима;
  advisor-режим можно закрыть обычным chat-completions.
