## Задача (постановка пользователя)

Поддержать в Vasyavig репозитории, ведущиеся с harness: в markdown-файлах
есть скрытые конверты с идентификаторами файлов (ULID). Требования:

1. Распознавать наличие ULID в документах.
2. В режиме просмотра (превью) ULID — кликабельные «ссылки» на документы,
   промаркированные штампом.
3. В режиме просмотра показывать имя и тип файла (из штампа).
4. Правки документов не должны разрушать конверты (исходный смысл задачи).

Будущее (не-цель, заявлено пользователем): просмотр дерева документов —
отдельная работа через графовую БД. Там же — дашборд задач по task-yaml.

## Исследование: формат harness-yaml

Реальный файл (план задачи) выглядит так (шапка, строки 1–19):

```markdown
<!-- [<[harness-yaml]]
id: 01M43R3ZGSNXQ0KSMZ9JSZEZ5W
project: lm_hrdo_2
title: "Etl Generator Entity Paths · 2026-09-21"
type: plan
created: 2026-09-21
related: []
[[harness-yaml]>] -->

> 🔖 **harness-yaml** · документ в реестре · id `01M43R3ZGSNXQ0KSMZ9JSZEZ5W` · метаданные — в source

<!-- [<[task-yaml]]
kind: daily-task
status: done
task: 20260921_622
tracker: ""
priority: ""
assignee: ""
[[task-yaml]>] -->
```

Факты (по коду harness-репо):

- **Конверт** — HTML-комментарий с маркерами `[<[harness-yaml]]` …
  `[[harness-yaml]>]`; ищется строго в первых 5 строках файла. Внутри —
  плоское YAML-подмножество: скаляры; строки с пробелами/кириллицей — в
  двойных кавычках (escape `\"`); списки инлайн `[a, b]`/`[]`. Обязательные
  поля: `id`, `project`, `title`, `type`, `created`; опциональные:
  `related`, `based_on` (списки ULID). Правило мутации: скаляры write-once,
  списки — только дозапись.
- **Закладка** — видимая строка-цитата с ULID в бэктиках; regex в
  `envelope.py`: `` harness-yaml.* id `([0-9A-Z]{26})` ``.
- **task-yaml** — второй скрытый конверт с теми же маркерами (другое имя) на
  задачных документах: `kind/status/task/tracker/priority/assignee`;
  мутабельные статус/приоритет/исполнитель.
- **Реестр** — `_docs_/_index/documents.jsonl` (коммитится; 1653 записи в
  примере): `{"ulid","path","project","title","type","created","updated",
  "related","based_on"}`, `path` — от корня репо, posix. Пересборка —
  `make doc-index` (Vasyavig реестр только читает).
- **ULID** — 26 символов Crockford base32 (алфавит без `I L O U`),
  лексикографически ≈ хронологичен; таймстемп — первые 10 символов (мс,
  epoch): современные ID начинаются на `01`.
- Охват штампования: `.md` в `_docs_/`, `docs/` минус `_index`, `sys_chat`,
  `sys_email` (конфиг `docid_config.json`).

## Исследование: сторона Vasyavig (где это ложится)

- **Round-trip WYSIWYG**: редактор открывается с `preset: "full"` и
  `md: {html: true, …}` (`MarkdownEditor.tsx`). В пресете `full` по цепочке
  `full-specs → yfm-specs → default-specs → commonmark-specs` подключён
  штатный **Html-экстеншн**: токены `html_block`/`html_inline` становятся
  atom-нодами с сырым содержимым в атрибуте, а сериализатор пишет атрибут
  обратно **дословно** (`state.write(node.attrs[html-content])`).
  Следствие: конверт-комментарий и task-yaml структурно переживают
  WYSIWYG→Markup→сохранение. Требует регресс-теста на байт-точность
  (EOL/пустые строки) — задача 4.
- **Markup-режим** (CodeMirror): файл правится как текст, конверт не
  преобразуется.
- **Сохранение**: `editorStore` пишет `tab.content` как есть (`writeFile`),
  EOL не переписывается.
- **Превью**: `SplitPreview.tsx` — `@diplodoc/transform` → DOM-проход
  `rewriteImageSrcs` (прецедент постобработки) → `DOMPurify.sanitize`.
  Линкификация ULID — ещё один DOM-проход до sanitize; клики — делегирование
  на контейнере (контент в `dangerouslySetInnerHTML`).
- **Навигация**: `fileStore.openFile(absPath)` открывает/активирует вкладку,
  докидывает гранты — переход по ULID = резолв + `openFile`.
- **Корень репо ≠ корень workspace**: индекс ищем подъёмом от каталога
  открытого файла до первого `_docs_/_index/documents.jsonl`.
- **Инвалидация кэша индекса**: watcher уже шлёт `fs-change` с путём
  (`useFileWatcher.ts`) — событие по пути индекса сбрасывает кэш.

## Цели

- **G1**: правки harness-markdown в Vasyavig (WYSIWYG, Markup, Ctrl+S) не
  меняют и не теряют конверты harness-yaml/task-yaml.
- **G2**: ULID распознаются в **превью и WYSIWYG**; известные реестру —
  кликабельные ссылки, открывающие документ (в т.ч. ULID из
  `related`/`based_on` в тексте и из закладки).
- **G3**: превью показывает имя (title) и тип (type) документа из конверта
  (fallback — имя файла).

## Решения

- **D1 — парсер конверта**: порт `harness_yaml.py` в TS
  (`src/lib/harnessEnvelope.ts`, ~60 строк): маркеры, окно 5 строк, снятие
  обёртки комментария, flat-YAML, кавычки/escape, инлайн-списки. Плюс:
  `parseBookmarkUlid(text)`, валидатор ULID (алфавит Crockford + длина) и
  проверка таймстемпа (декодировать первые 10 символов, ограничение
  2020–2100) — отсекает ложные срабатывания на случайных 26-символьных
  токенах.
- **D2 — сохранность конверта**: опираемся на штатный Html-экстеншн Gravity,
  защитный слой «вырезать до редактора / вернуть при сохранении» НЕ вводим:
  он прячет конверт из Markup-режима и ломает dirty-сравнение. Риск
  случайного удаления пользователем в WYSIWYG (Ctrl+A → Delete сносит и
  атомы) принимаем — как и удаление видимой закладки; write-once-политика и
  `make doc-check` в harness-репо ловят такие потери. Если регресс-тест
  (задача 4) покажет потери — вернуться к защитному слою (отдельное решение).
- **D3 — распознавание ULID в превью**: DOM-проход по текстовым узлам
  (включая `<code>` — ULID в закладке в бэктиках): валидный по D1 ULID,
  найденный в реестре, оборачивается в `<a data-ulid="…">` с `title`
  «title · type»; валидный, но не найденный — `<span data-ulid-unknown>`
  (немая подсветка, title «нет в реестре»). Последовательности, не прошедшие
  timestamp-фильтр, не трогаются.
- **D4 — реестр**: `src/lib/harnessIndex.ts` + `src/store/harnessStore.ts`:
  подъём от каталога файла (≤10 уровней) до `_docs_/_index/documents.jsonl`;
  парсинг JSONL → `Map<ulid, entry>` (+ префиксный поиск, как `doc-find`);
  кэш по корню репо; ленивая загрузка при открытии markdown-вкладки с
  конвертом; сброс кэша по `fs-change` на путь индекса. Размер (1653 записи,
  ~0,5 МБ) — не проблема.
- **D5 — переход**: клик-делегирование в `SplitPreview`: `a[data-ulid]` →
  резолв (полный ULID; неоднозначный префикс — не переходим, toast) →
  `fileStore.openFile(<корень репо>/<path>)`. Нет файла на диске — toast с
  ошибкой. i18n: ru/en строки.
- **D6 — имя и тип в превью**: компактная шапка панели превью (в
  `SplitView`/`SplitPreview`): `title` + бейдж `type` из конверта текущего
  файла (парсинг первых 5 строк контента, синхронно, без индекса); нет
  конверта — имя файла.
- **D7 — линкификация в WYSIWYG** (решение пользователя по вопросу 1):
  extension-плагин по образцу `spellcheckExtension.ts`
  (`src/lib/harnessUlidExtension.ts`, подключение в `combineExtensions` в
  `MarkdownEditor.tsx`): inline-декорации `Decoration.inline` на диапазонах
  текста, совпавших с ULID, — класс `ulid-link` (в реестре) /
  `ulid-unknown` (нет в реестре), title-атрибут «title · type». Декорации
  view-only: документ и сериализация не затрагиваются, round-trip безопасен.
  Клик — через `handleClickOn`/DOM-слушатель на элементе декорации: резолв
  через harnessStore → `fileStore.openFile`. Пересборка декораций — на
  change документа (regex-поиск по textblock'ам, дёшево; дебаунс не нужен).
- **D7a — сфера**: markdown-вкладки — превью (split) и WYSIWYG. Подсветка в
  Markup-режиме (CodeMirror) и просмотрщики (.html/.eml) — вне рамок.
- **D8 — task-yaml**: обеспечиваем только сохранность (тот же механизм
  комментария, D2); интерпретация полей (дашборд задач) — future вместе с
  графовой БД.
- **D9 — панель связей конверта** (доработка по GUI-приёмке 2026-10-25):
  скрытые ULID из `related`/`based_on` недоступны в рендере (конверт —
  комментарий). В превью под шапкой — панель чипов: known → кликабельный
  чип «title» (tooltip «title · type», метка «осн.» у based_on), unknown —
  пунктирный неактивный чип с ULID и подсказкой. Клик — тот же
  `openUlidTarget`. ULID в теле документа (будущая интеграция) покрыты
  линкификацией D3/D7 без изменений.
- **D10 — оглавление после harness-шапки** (доработка по GUI-приёмке):
  `applyTocInsert` вставлял блок «Оглавление» в строку 1 — конверт вылетал
  из окна первых 5 строк и ломался. Теперь вставка после шапки: ведущие
  HTML-комментарии (конверт, task-yaml) + закладка-цитата + пустые строки
  между ними (`harnessHeaderEndLine`); frontmatter (`--- … ---`) также
  остаётся первым блоком. Файл без шапки — прежнее поведение (в начало).

## Не-цели

- Дерево/граф документов, дашборд задач по task-yaml (future, графовая БД).
- Создание/мутация конвертов и реестра из Vasyavig (зона `make doc-id` /
  `make doc-index` в harness-репо).
- Подсветка ULID в Markup-режиме (CodeMirror) и просмотрщиках.
- Поддержка не-markdown файлов со штампом.

## Проверки

- `pnpm test`, `npx tsc --noEmit`, `npx vite build` — без регрессий.
- GUI-чек-лист (на реальном `lm_hrdo_2`):
  1. Открыть план задачи → split-превью: шапка «title · type», закладка
     видна, ULID подчёркнут ссылкой.
  2. Кликнуть ULID в закладке и в теле (related-упоминания) — в превью и в
     WYSIWYG → открывается целевой документ, вкладка активируется.
  3. Ввести в текст чужой ULID — помечен «нет в реестре», не кликается.
  4. Правка в WYSIWYG + Ctrl+S → `git diff`: конверт/закладка/task-yaml
     нетронуты (только правка). То же для Markup-режима.
  5. Файл без конверта — превью без изменений (кроме обычного рендера).

## Риски

- Байт-точность round-trip (нормализация пустых строк/EOL сериализатором) —
  закрывается задачей 4; прецедент: `experimental.preserveEmptyRows: true`
  уже включён.
- DOMPurify может вырезать HTML-комментарии из превью — на файл не влияет
  (конверт живёт в источнике), закладка видна; проверить в задаче 3.
- Ложные срабатывания на 26-символьных токенах — timestamp-фильтр D1 +
  ссылки только для известных реестру.
- Изменение формата harness в будущем (поля/маркеры) — парсер строго по
  маркерам, неизвестные поля игнорирует; реестр — источник правды для ссылок.

## Решения по открытым вопросам (закрыты пользователем 2026-10-25)

1. Кликабельные ULID — **и в превью, и в WYSIWYG сразу** (не откладываем
   WYSIWYG на будущие задачи) → решения D7, задача 3a.
2. Шапка превью — **`title` + `type` из конверта**, fallback на имя файла
   (D6 подтверждён).
3. Валидный ULID вне реестра — **тихая подсветка** с подсказкой «нет в
   реестре», без перехода (D3 подтверждён).
