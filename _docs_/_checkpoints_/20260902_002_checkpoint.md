## Implemented features

Change `20260902-editor-ux-fixes` (13/13 задач, ручной чек-лист пользователя
2026-09-02 пройден):

- **Горизонтальная полоса прокрутки документа**: WYSIWYG — широкие таблицы не
  сжимаются (word-wrap ячеек вместо break-spaces), скроллер редактора даёт
  полосу на весь документ; Markup — строки без переноса (как VS Code), полоса
  на весь документ; превью — без изменений (штатный per-table скролл diplodoc,
  решение пользователя).
- **Стабильность каркаса**: футер не растёт (кап высоты строки статус-бара),
  основная строка grid не распирается, sticky-измерения тулбара отключены.
  Симптомы (пропадение панелей при ресайзе/переключении файлов) не
  воспроизводятся после фикса; точный корень не доказан — закрыт класс
  симптомов защитной связкой (см. Known gaps).
- **Preview-вкладки** (семантика VS Code): одиночный клик — курсивная
  эфемерная вкладка (замещает предыдущую preview без промпта), двойной клик
  или первая правка — закрепление (необратимо), Ctrl+O / drop файла /
  конвертация — сразу закреплённые.

## Known gaps / NOT done

- Корень бага каркаса не идентифицирован точно (перемежающийся, живой репро в
  быстрой сессии не воспроизвёлся): применена защитная связка (кап футера +
  minmax + stickyToolbar=false). Если симптомы вернутся — репро с DevTools
  (Ctrl+Shift+I в dev-сборке), кандидат в новый change.
- Preview-вкладки не персистентны между запусками (вкладки и не были).
- Горизонтальный скролл код-блоков в WYSIWYG — вне скоупа (кандидат в беклог).

## Key decisions & constraints

- Порядок CSS-бандла: `main.tsx` импортирует App (и его CSS) РАНЬШЕ gravity
  styles → равная специфичность проигрывает gravity. Перекрытия gravity-стилей
  делать с запасом специфичности (`.editor-area .md-editor .ProseMirror …`,
  3+ класса).
- CM6 определяет перенос строк по computed `white-space` контента
  (HeightOracle.refresh) — CSS-откат `pre` корректно переключает и измерения.
- `.yfm` класс есть и у WYSIWYG-контента (`yfm yfm-editor ProseMirror`), не
  только у превью — правила diplodoc `.yfm table` действуют и в редакторе.
- Закрепление preview — по переходу в dirty (`content !== savedContent`), не по
  событию `change` (программные события не закрепляют).
- Двойной клик в дереве не требует задержки: первый клик уже открыл preview,
  dblclick закрепляет.
