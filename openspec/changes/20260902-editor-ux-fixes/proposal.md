# Proposal: editor UX — широкие таблицы, стабильность layout, preview-вкладки

## Why

Три проблемы из реального пользования редактором. (1) В документации встречаются
очень широкие markdown-таблицы: word wrapping работает, но широкий блок либо
растягивает контент, либо недоступен для просмотра целиком — нужен
горизонтальный скролл у самого блока. (2) Раскладка нестабильна: при изменении
размера окна и после «открыть другой файл и вернуться» пропадает хедер с
кнопками режимов и растёт футер; лечится только перекликиванием файлов. (3)
Вкладки замусориваются: каждый клик по файлу в дереве создаёт постоянную
вкладку, хотя пользователь просто просматривал файл.

## What Changes

- **Широкие таблицы не сжимаются**: очень широкие таблицы в WYSIWYG получают
  горизонтальную полосу прокрутки всего документа (уточнение пользователя:
  полоса для документа, не для отдельной таблицы); Markup-режим — без
  переноса строк, с такой же полосой на весь документ (как в VS Code); в
  превью таблица скроллится в своей области (штатное поведение рендера,
  решение пользователя). Перенос строк и остальная раскладка не меняются.
- **Стабильный каркас приложения**: тулбар/хедер и футер не пропадают и не
  растут при ресайзе окна и переключении файлов — раскладка восстанавливается
  без «перекликивания». Включает диагностику корня (подозреваемые:
  `stickyToolbar` редактора, устаревшие измерения после ремоунта `key={path}`,
  grid-строка `auto` у статус-бара).
- **Preview-вкладки** (семантика VS Code): одиночный клик по файлу в дереве
  открывает эфемерную вкладку просмотра; двойной клик или первая правка
  закрепляют вкладку; переход к другому файлу закрывает незакреплённую вкладку
  (промпт не нужен — она не бывает dirty). Ctrl+O и drag-and-drop файла
  открывают сразу закреплённую вкладку. Семантика распространяется на все типы
  вкладок; правка-закрепление — только для редактируемых (markdown).

## Capabilities

### New Capabilities

- `wide-content-scrolling`: широкие блоки контента (таблицы) в редакторе и
  превью скроллятся горизонтально внутри собственной области, не ломая
  раскладку редактора и не включая прокрутку всего документа.
- `layout-stability`: каркас приложения (тулбар, панель вкладок, статус-бар)
  стабилен при изменении размера окна и переключении файлов — панели не
  пропадают, футер не растёт.
- `preview-tabs`: эфемерные вкладки просмотра из навигации — закрепление
  двойным кликом или первой правкой, автозакрытие незакреплённой вкладки при
  переходе к другому файлу, визуальное отличие от закреплённых.

### Modified Capabilities

Нет — существующие спеки (`multi-root-workspace`, `workspace-file`,
`folder-colors`) не затронуты.

## Impact

- `src/components/EditorArea/EditorArea.css` — CSS: отмена сжатия таблиц
  WYSIWYG (документ-левел горизонтальный скролл) с запасом специфичности
  против gravity-стилей (решение — в design D1).
- `src/components/EditorArea/SplitPreview.tsx` + CSS превью — обёртка
  отрендеренных таблиц с `overflow-x: auto`.
- `src/components/Layout.css`, `src/components/EditorArea/EditorArea.css`,
  `MarkdownEditor.tsx` (`stickyToolbar`) — фикс стабильности панелей после
  диагностики.
- `src/store/editorStore.ts` — флаг preview/pinned у `EditorTab`; продвижение в
  pinned при `updateContent`; замена preview-вкладки при новом preview-открытии.
- `src/store/fileStore.ts` (`openFile`) — режим открытия (preview/pinned).
- `src/components/Sidebar/FileTreeNode.tsx` — обработчик двойного клика.
- `src/components/EditorArea/EditorTabs.tsx` — визуальное отличие preview-вкладки.
- Локали `src/locales/{ru,en}` — при необходимости новые строки.
- Тесты: vitest (`editorStore` — preview-семантика), ручной чек-лист
  (широкие таблицы, ресайз, сценарии вкладок).
