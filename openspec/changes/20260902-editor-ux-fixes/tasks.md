# Tasks: editor UX — широкие таблицы, стабильность layout, preview-вкладки

> Спецификации поведения — specs/, подход — design.md.

## 1. Широкие таблицы: горизонтальный скролл блока

- [x] 1.1 WYSIWYG: широкие таблицы не сжимаются — документ получает
  горизонтальную полосу прокрутки. Чистый CSS с запасом специфичности против
  `.yfm table` / break-spaces gravity (design D1; уточнение пользователя:
  полоса для всего документа, не per-table — первая версия с nodeview-обёрткой
  демонтирована). Проверка: ручная — документ с таблицей в 10+ колонок:
  полоса внизу области редактора, таблица естественной ширины, текст вне
  таблицы не сжимается; каретка в ячейке за краем прокручивает документ к себе.
- [x] 1.2 Превью: CSS для таблиц в панели split-превью (design D2). Проверка:
  ручная — та же широкая таблица в split: скролл у таблицы, панель превью не
  скроллится по горизонтали целиком.
- [x] 1.4 Markup-режим: без переноса строк — горизонтальная полоса на весь
  документ, как в VS Code (уточнение пользователя 2026-09-02; CSS-откат
  `lineWrapping`, mechanism — design D1). Проверка: ручная — документ с
  длинными строками (широкая таблица в pipe-синтаксисе) в Markup: строки не
  переносятся, полоса внизу редактора.
- [x] 1.3 Регресс переноса строк: обычные абзацы и узкий контент рендерятся как
  до изменения, в обеих темах. Проверка: ручная — документ без таблиц + обе
  темы; горизонтального скролла вне таблиц нет.

## 2. Стабильность каркаса: диагностика и фикс

- [x] 2.1 Диагностика бага по сценарию пользователя (ресайз окна + «открыть
  другой файл и вернуться») в dev-сборке с WebView2 DevTools: зафиксировать
  репро, снять DOM-состояние сломанного момента (высоты/offsets статус-бара и
  тулбара), проверить гипотезы design D3 (stickyToolbar, переполнение grid
  `100vh`, `min-height: 0` в flex-цепочке), записать вывод о корне. Проверка:
  вывод зафиксирован (результат задачи в `_tasks_/` или чекпойнт); репро
  стабильно воспроизводится или опровергается.
- [x] 2.2 Фикс по найденной причине (точечный; для stickyToolbar — точечный
  фикс, при невозможности — отключение, design D3). Проверка: ручной чек-лист
  по спеке `layout-stability` — несколько ресайзов подряд, минимальная ширина
  окна, открыть-другой-файл-и-вернуться: кнопки режимов видимы, футер одной
  строки, без «перекликивания».
- [x] 2.3 Регресс каркаса: повторить чек-лист во всех режимах (wysiwyg /
  markup / split) и на не-markdown вкладке (Monaco), в обеих темах. Проверка:
  ручная — симптомы не воспроизводятся ни в одной комбинации.

## 3. Preview-вкладки

- [x] 3.1 `editorStore`: флаг `preview` у `EditorTab`; `openTab` c опцией —
  preview-открытие закрывает предыдущую preview-вкладку другого пути,
  закреплённое открытие существующей preview её закрепляет; закрепление при
  переходе в dirty внутри `updateContent` (design D4). Проверка: vitest —
  сценарии спеки: последовательные preview A→B→C оставляют одну вкладку,
  повторный клик по тому же файлу не создаёт дубль, первая правка закрепляет,
  закреплённые вкладки не закрываются, preview не бывает dirty.
- [x] 3.2 `fileStore.openFile(path, {preview})` (дефолт — закреплённая) и
  проводка из дерева: одиночный клик — preview, `onDoubleClick` в
  `FileTreeNode` — закреплённая. Проверка: vitest на проводке стора + ручная —
  одиночный/двойной клик по файлу с уже открытой preview закрепляет её.
- [x] 3.3 Визуальное отличие preview-вкладки: курсив подписи (design D6).
  Проверка: ручная — preview и закреплённая вкладки различимы, в обеих темах.
- [x] 3.4 Явные открытия — закреплённые: drag-and-drop файла, Ctrl+O, вкладка
  после конвертации office. Проверка: ручная — все три пути дают закреплённую
  вкладку при открытой preview.
