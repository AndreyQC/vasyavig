# Design: editor UX — широкие таблицы, стабильность layout, preview-вкладки

> Контекст: proposal.md (зачем), specs/ (поведенческие требования).
> Кодовая база: чекпойнт `20260902_001`, уроки `LESSONS_LEARNED.md` §3, §8, §10, §11.

## Context

Редактор markdown — Gravity `markdown-editor` (`MarkdownEditor.tsx`), монтируется
с `key={path}` (переключение файла = полный ремоунт). WYSIWYG-таблицы —
расширение YfmTable на базе prosemirror-tables; превью — HTML из
`@diplodoc/transform` (`SplitPreview.tsx`). Каркас: CSS-grid `.layout`
(`Layout.css`) со строками `1fr auto` (статус-бар — `auto`), внутри
`.editor-area` — flex-колонка: тулбар, вкладки, контент (`overflow: hidden`).
`MarkdownEditorView` использует `stickyToolbar`. Вкладки — плоский список в
`editorStore` (`EditorTab` без статуса закрепления); файлы открывает
`fileStore.openFile` из дерева (`FileTreeNode`) и drag-and-drop (`useDragDrop`).

## Goals / Non-Goals

**Goals:**

- Широкие таблицы скроллятся внутри себя в WYSIWYG и превью, минимальным
  вмешательством во внутренности Gravity-редактора.
- Найти и устранить корень нестабильности каркаса (диагностика до фикса, не
  «косметическая заплатка» симптома).
- Preview-вкладки без изменения персистентности (вкладки всё равно не
  восстанавливаются между запусками — флаг не сохраняется нигде).

**Non-Goals:**

- Горизонтальный скролл код-блоков и других блочных элементов (только таблицы;
  код — кандидат в беклог).
- Настройка «открывать всегда закреплённой» (поведение фиксировано).
- Персистентность статуса вкладок между запусками, восстановление сессии.
- Переезд на другую grid/flex-архитектуру каркаса — меняем точечно.

## Decisions

### D1. Таблицы WYSIWYG: чистый CSS, полоса прокрутки у всего документа

Таблицы не сжимаются: отменяем `.yfm table` (inline-block + max-width:100%)
и break-spaces ячеек (`.yfm.yfm-editor table th/td/code`) селекторами
`.editor-area .md-editor .ProseMirror table …` с запасом специфичности —
gravity-стили грузятся в CSS-бандле после наших (main.tsx импортирует App
раньше styles), равная специфичность проигрывает каскад. Таблица
естественной ширины переполняет скроллер редактора
(`.g-md-wysiwyg-editor__editor`, overflow-y: auto → вторая ось вычисляется
в auto), и весь документ получает горизонтальную полосу — по уточнению
пользователя («полоса для всего документа», не per-table).

Альтернативы отклонены: nodeview-обёртка с локальным overflow (первая
версия, противоречит уточнённому требованию); CSS-хак `table { display:
block }` (ломает табличный layout). Перенос ячеек возвращается к word-wrap:
min-content колонки = самое длинное слово, а не символ.

Markup-режим (уточнение пользователя, там же): CodeMirror переносит строки —
`EditorView.lineWrapping` включён в `createCodemirror` без публичной опции
отключения. CM6 определяет режим переноса по computed `white-space`
контента (HeightOracle.refresh), поэтому CSS-откат
`.cm-lineWrapping .cm-content { white-space: pre }` отключает и перенос, и
измерения высот CM; горизонтальную полосу даёт штатный `.cm-scroller`
(overflow: auto). Превью остаётся со скроллом таблицы в своей области
(решение пользователя).

### D2. Таблицы превью: чистый CSS

Превью — статический HTML (без ProseMirror), поэтому CSS допустим и достаточен:
контейнеру превью `table { display: block; overflow-x: auto; max-width: 100% }`.
Без JS-прохода по DOM и без обёрток в разметке.

### D3. Нестабильность каркаса: сначала диагностика с репро, фикс по находке

Баг воспроизводится по сценарию пользователя: ресайз окна + «открыть другой
файл и вернуться» (ремоунт `key={path}` сбрасывает симптомы — указывает на
устаревшие измерения, а не на структурную поломку CSS). Порядок работ:

1. Зафиксировать репро в dev-сборке (WebView2 DevTools), снять DOM-состояние
   панелей в сломанный момент (какая высота/offset у статус-бара, где тулбар).
2. Проверить гипотезы по убыванию вероятности:
   - `stickyToolbar` редактора: sticky-тулбар тулбара Gravity относительно
     скролл-контейнера с устаревшим измерением после ресайза;
   - переполнение grid: `.layout { height: 100vh }` + строки `1fr auto` — при
     рассинхроне высоты viewport и grid статус-бар «выдавливается»/растёт;
   - flex-цепочка без `min-height: 0`/`min-width: 0` где-то между
     `.layout__main` и `.md-editor` (урок §8).
3. Точечный фикс по найденной причине; если причина — stickyToolbar и точечный
   фикс невозможен, отключаем `stickyToolbar` (тулбар скроллится с контентом —
   приемлемая деградация, стабильность важнее).

Альтернатива «сразу переписать layout» отклонена: без понимания корня легко
заменить один баг другим.

### D4. Preview-вкладки: флаг `preview` в `EditorTab`, максимум одна

```ts
interface EditorTab {
  ...
  preview: boolean;   // true — эфемерная вкладка просмотра
}
```

Права на статус:
- `openTab(tab, {preview})`: при `preview: true` закрывает существующую
  preview-вкладку другого пути (без промпта — она не бывает dirty), затем
  открывает новую с `preview: true`; при `preview: false` — если вкладка этого
  пути уже есть, снимает `preview` (закрепляет), иначе создаёт закреплённую.
- `updateContent`: вкладка закрепляется при переходе в dirty
  (`content !== savedContent`), не по факту события `change` — события приходят
  и от программных источников (переключение режима), они не должны закреплять.
  Закрепление необратимо в рамках сессии вкладки.

Инвариант: preview-вкладка никогда не dirty (первая правка закрепляет), поэтому
её автозакрытие и ручное закрытие не требуют промптов — существующая логика
`CloseTabModal` не меняется.

### D5. Маршрутиция режимов открытия через `fileStore.openFile(path, opts)`

Единственные точки открытия файлов — `FileTreeNode` (дерево) и `useDragDrop`
(drop файла). `openFile` получает опцию открытия (по умолчанию — закреплённая):

- одиночный клик в дереве: `openFile(path, {preview: true})`;
- двойной клик в дереве: `onDoubleClick` → `openFile(path)` (закреплённая).
  Специальная обработка «дождаться dblclick» не нужна: первый клик уже открыл
  preview, dblclick закрепляет её — семантика VS Code;
- drag-and-drop файла, Ctrl+O, результат конвертации office — закреплённая
  (явное намерение пользователя, дефолт `openFile`).

### D6. Визуальное отличие: курсив подписи preview-вкладки

CSS-класс на подписи вкладки (`font-style: italic`), как в VS Code. Без
изменения тинта корня: цветовая система занята семантикой корня (спека
folder-colors), смешение смыслов усложнит восприятие.

## Risks / Trade-offs

- [У YfmTable свой nodeView таблицы, конфликт с обёрткой] → перекрытие через
  `builder.addPlugin(..., Priority.Highest)` (урок §10); временный
  `console.log` в фабрике nodeView для проверки, что наш view применяется.
- [Корень бага каркаса вне трёх гипотез] → диагностика (D3) вынесена отдельной
  задачей ДО фикса; чек-лист спеки `layout-stability` — критерий готовности
  фикса, а не самой диагностики.
- [Программные `change`-события закрепляют preview-вкладку] → закрепление по
  переходу в dirty, не по событию (D4).
- [Отключение `stickyToolbar` (если до этого дойдёт) ухудшит UX длинных
  документов] → осознанный трейд-офф в пользу стабильности; возврат отдельной
  задачей после фикса корня.

## Migration Plan

Персистентных форматов нет — миграция не нужна. Откат — revert коммитов; риски
локализованы в перечисленных файлах Impact proposal.

## Open Questions

- Точная точка подключения scroll-обёртки таблиц в WYSIWYG (готовая
  `.tableWrapper` от YfmTable vs свой nodeView) — решается при реализации по
  факту внутренностей пакета; на спеку и разбивку задач не влияет.
- Нужно ли продублировать scroll для широких код-блоков — вне скоупа, кандидат
  в беклог roadmap.
