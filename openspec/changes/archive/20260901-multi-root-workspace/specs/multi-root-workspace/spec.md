# multi-root-workspace

## Purpose

Позволяет работать одновременно с несколькими корневыми папками как с единым
workspace: секции дерева на каждый корень, общие вкладки, живое обновление
деревьев, корректные краевые случаи (вложенные корни, файлы вне корней).

## ADDED Requirements

### Requirement: Workspace как список корней

Система SHALL поддерживать workspace из нуля и более корневых папок. Порядок
корней детерминирован (в порядке добавления). Каждая корневая папка отображается
в сайдбаре отдельной секцией дерева со своим заголовком.

#### Scenario: Первая папка

- **WHEN** пользователь добавляет папку в пустой workspace
- **THEN** папка становится единственным корнем и её дерево отображается в
  сайдбаре одной секцией

#### Scenario: Пустой workspace

- **WHEN** в workspace нет ни одного корня
- **THEN** сайдбар показывает пустое состояние с возможностью добавить папку

### Requirement: Добавление корня не разрушает сессию

Добавление папки в workspace SHALL происходить без закрытия открытых вкладок и
без запросов о несохранённых изменениях. Добавление папки, уже являющейся
корнем (тот же путь), — no-op.

#### Scenario: Второй корень

- **WHEN** в workspace один корень и открыты вкладки, и пользователь добавляет
  вторую папку
- **THEN** обе секции отображаются в сайдбаре, все вкладки и несохранённые
  правки сохраняются

#### Scenario: Повторное добавление того же корня

- **WHEN** пользователь добавляет папку, путь которой уже есть в списке корней
- **THEN** состав workspace и порядок корней не меняются, дубликат не создаётся

### Requirement: Удаление корня с защитой несохранённых вкладок

При удалении корня из workspace система SHALL закрыть вкладки файлов этого
корня. Если среди них есть несохранённые изменения, удаление SHALL требовать
явного подтверждения; при отказе корень остаётся в workspace. Вкладки других
корней не затрагиваются.

#### Scenario: Удаление корня без несохранённых вкладок

- **WHEN** пользователь удаляет корень, вкладки его файлов чистые
- **THEN** корень исчезает из сайдбара, его вкладки закрываются, остальные
  вкладки остаются

#### Scenario: Удаление корня с несохранёнными вкладками

- **WHEN** пользователь удаляет корень, у его вкладок есть несохранённые правки,
  и подтверждение отклонено
- **THEN** корень и вкладки остаются без изменений

### Requirement: Вложенные корни

Если один корень расположен внутри другого, оба SHALL отображаться как
самостоятельные секции. Файл или папка относится к наиболее глубокому корню,
содержащему её путь.

#### Scenario: Папка внутри корня добавлена отдельно

- **WHEN** корни `C:/docs` и `C:/docs/guides`, пользователь открывает файл
  `C:/docs/guides/intro.md`
- **THEN** файл считается принадлежащим корню `C:/docs/guides`

### Requirement: Файлы вне корней остаются доступны

Файлы, открытые минуя дерево (диалог открытия, drag-and-drop файла), SHALL
открываться во вкладках и не отображаться в дереве workspace.

#### Scenario: Открытие файла вне корней

- **WHEN** в workspace есть корни, пользователь открывает файл вне их через
  диалог открытия файлов
- **THEN** файл открывается вкладкой и не появляется ни в одной секции дерева

### Requirement: Живое обновление деревьев по корню

Система SHALL отслеживать изменения файловой системы каждого корня и обновлять
дерево затронутого корня. Изменения вне корней не инициируют обновление деревьев.

#### Scenario: Изменение в одном из корней

- **WHEN** в корне A на диске создаётся файл, в workspace корни A и B
- **THEN** обновляется дерево корня A, дерево корня B не перезагружается
