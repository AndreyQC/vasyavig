# Tasks: multi-root workspace с цветами папок

> Спецификации поведения — specs/, подход — design.md.

## 1. Фундамент: модель и цвета

- [x] 1.1 Ввести тип `RootColor` (9 токенов + `neutral`) и CSS-переменные
  `--root-tint-<name>` / `--root-accent-<name>` для light/dark тем
  (`color-mix` с фоном темы). Проверка: `npx tsc --noEmit` чист; визуально оба
  темы дают различимый тинт без потери читаемости текста.
- [x] 1.2 Утилиты: нормализатор путей и `resolveRoot(path, roots)` — самое
  длинное совпадение префикса с границей разделителя. Проверка: vitest-кейсы
  `C:/docs` vs `C:/docs2`, `C:/DOCS` vs `c:/docs`, вложенные корни, файл вне
  корней → null.
- [x] 1.3 `fileStore`: `roots: RootInfo[]`, `trees: Record<string, FileNode[]>`,
  экшены `addRoot`/`removeRoot`/`refreshRoot` (grant_asset_scope на каждый
  корень; `expandedPaths` общие). Проверка: vitest — добавление не трогает
  вкладки, повторное добавление no-op, удаление одного корня не затрагивает
  дерево другого; селекторы не создают новых объектов (аудит по §3).

## 2. Файл workspace

- [x] 2.1 Сериализация/парсинг `.vasyavig-workspace` (version 1, folders c
  path+color; относительные пути к каталогу файла, абсолютные при другом
  диске). Проверка: vitest — roundtrip абсолютные↔относительные, чужая версия
  формата → ошибка, не краш.
- [x] 2.2 Автозапись: любое изменение состава/цвета немедленно пишет файл;
  при добавлении первого корня без файла — диалог выбора места. Проверка:
  vitest на экшенах стора (мок FS) + ручная — файл на диске актуален.
- [x] 2.3 Восстановление: путь последнего workspace в persist `uiStore`;
  на старте загрузка, при отсутствии/ошибке — чистый старт. Проверка: ручная —
  перезапуск `tauri dev` восстанавливает корни и цвета; удаление файла →
  пустой сайдбар.
- [x] 2.4 «Открыть workspace» / «Новый workspace» с dirty-подтверждением
  (`pendingOpenWorkspacePath` / `pendingNewWorkspace` в `uiStore`; убрать
  `pendingOpenFolderPath`). Проверка: vitest на сторе + ручная — отказ в
  промпте оставляет текущий workspace.

## 3. Rust-watcher

- [x] 3.1 `WatcherState` → один `RecommendedWatcher` + `HashSet` смотренных
  путей; `watch_folder`/`unwatch_folder`; payload `{path}` у события
  `fs-change`; unwatch не-смотренного — warn, не ошибка. Проверка:
  `cargo test` (мульти-watch, unwatch, payload).
- [x] 3.2 `useFileWatcher`: событие → `resolveRoot` → refresh только затронутого
  дерева, дебаунс 300 мс на корень. Проверка: ручная с рестартом `tauri dev`
  (урок §11): файл в корне A обновляет только дерево A.

## 4. Сайдбар: секции-корни

- [x] 4.1 `RootSection`: заголовок (имя, color chip, контекст-меню «сменить
  цвет» / «убрать из workspace»), фон секции = тинт. Проверка: ручная — смена
  цвета мгновенно перекрашивает секцию и вкладки корня.
- [x] 4.2 Шапка сайдбара: «Добавить папку», «Открыть workspace», «Новый
  workspace»; демонтировать блок «Текущая директория» Phase 6. Проверка:
  ручная + скрин обеих тем.
- [x] 4.3 Удаление корня: dirty-вкладки его файлов → промпт; подтверждение
  закрывает вкладки корня и убирает корень. Проверка: vitest на
  `removeRoot`/`editorStore` + ручная.
- [x] 4.4 Локали ru/en для всех новых строк. Проверка: переключение языка —
  нет ключей-заглушек.

## 5. Вкладки и drag-and-drop

- [x] 5.1 `EditorTabs`: тинт фона вкладки по `resolveRoot` (через `useMemo`,
  не селектор), вне корней — нейтральный; активная вкладка — широкая рамка
  `outline` цвета корня, старую заливку `--active` убрать. Проверка: ручная —
  активация не сдвигает соседние вкладки, скролл-цепочки не ломаются (§8).
- [x] 5.2 `useDragDrop`: drop папки → `addRoot` (не замена), drop файла —
  как сейчас. Проверка: ручная — вкладки и dirty-состояние переживают drop.

## 6. Интеграционные проверки

- [x] 6.1 Полный прогон: `npx pnpm@11.24.0 test`, `npx tsc --noEmit`,
  `cargo test --manifest-path src-tauri/Cargo.toml` — все зелёные.
- [x] 6.2 Ручной чек-лист сценария из спек: два корня разных цветов, вложенные
  корни, файл вне корней (серый), 10-й корень повторяет цвет, перезапуск
  восстанавливает workspace, удаление корня с dirty-вкладкой — промпт.
  Результат зафиксировать в чекпойнте фазы.
