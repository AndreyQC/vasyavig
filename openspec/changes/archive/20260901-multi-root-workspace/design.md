# Design: multi-root workspace с цветами папок

> Контекст: proposal.md (зачем), specs/ (поведенческие требования).
> Кодовая база: чекпойнт `20260831_002`, уроки `LESSONS_LEARNED.md` §3, §8, §11.

## Context

Сейчас `fileStore` держит единственный `rootPath: string | null`, одно дерево
`tree: FileNode[]` и одну запись `expandedPaths`; Rust `WatcherState` —
`Mutex<Option<RecommendedWatcher>>` (одна папка, новая заменяет старую). Табы в
`editorStore` — плоский список без связи с корнем. Событие `fs-change` из Rust
не несёт пути. Все FS-операции идут через кастомные команды (Tauri fs-plugin
scopes не используются), `grant_asset_scope` вызывается на папку.

## Goals / Non-Goals

**Goals:**

- Модель N корней с минимальной ползучестью изменений по существующим сторам.
- Цвет как производное от (путь → корень), без дублей правды в табах.
- Тема-независимые цвета (light/dark) без рантайм-математики в JS.
- Файл workspace как единственный источник персистентности состава.

**Non-Goals:**

- Переупорядочивание корней drag-and-drop, папки-группы корней.
- Live-reload workspace-файла при внешнем редактировании (last-write-wins).
- OS-ассоциация расширения `.vasyavig-workspace` с приложением.
- Цветовая маркировка в статус-баре/заголовке окна.

## Decisions

### D1. Модель стора: `roots` + деревья по ключу корня

```ts
interface RootInfo { path: string; color: RootColor }  // RootColor = имя токена палитры
// fileStore:
roots: RootInfo[];                        // порядок = порядок добавления
trees: Record<string, FileNode[]>;        // ключ — путь корня
expandedPaths: Record<string, true>;      // остаётся общей: пути уникальны
```

Альтернатива — фейковый супер-узел в одном дереве — отклонена: смешивает
UI-артефакт с данными, ломает существующие рекурсии `FileTree`.

`isLoadingTree`/`error` остаются скалярными: загрузка корней независимая,
деградация одного корня не блокирует остальные.

### D2. Резолвинг путь → корень: чистая функция, `useMemo`, не селектор

`resolveRoot(path, roots): RootInfo | null` — самое длинное совпадение префикса
с проверкой границы разделителя (`C:/docs` не матчит `C:/docs2`). Вызывается в
компонентах через `useMemo([path, roots])`. Селекторы Zustand, возвращающие
новые объекты, запрещены — урок §3 (главный источник «белого окна»). Табы цвет
не хранят: он всегда производен, иначе дубль правды и рассинхрон при
добавлении/удалении корней.

### D3. Цвета — именованные токены + CSS-переменные

Палитра: 9 имён (red, orange, amber, lime, teal, cyan, blue, violet, pink).
В workspace-файле хранится **имя**, не hex. Для каждой темы (light/dark) в CSS
определены `--root-tint-<name>` (фоновый тинт) и `--root-accent-<name>`
(насыщенный, рамка), значения через `color-mix(in srgb, ...)` с фоном темы.

Альтернатива — hex в файле — отклонена: ломает двойную тему, менее переносимо.
Нейтральный серый (`--root-tint-neutral`) не входит в палитру и выдаётся
резолвером для файлов вне корней.

Авто-выдача: первый свободный цвет по кругу от индекса последней выдачи; при
исчерпании — с начала палитры.

### D4. Рамка активной вкладки — `outline`, не `border`

`outline: 2px solid var(--root-accent-<name>); outline-offset: -1px` — не
участвует в layout: активация вкладки не сдвигает соседние и не дёргает
flex-цепочку со скроллом (урок §8). `border` отклонён из-за сдвига геометрии.
Заливка активной вкладки (текущий `--active`) убирается; у неактивных вкладок
фон = тинт корня.

### D5. Watcher: один `RecommendedWatcher`, много `watch()`

`WatcherState` → `Mutex<WatchState>`, где `WatchState { watcher:
RecommendedWatcher, watched: HashSet<String> }`. Добавление корня —
`watcher.watch(path)`, удаление — `watcher.unwatch(path)` (крэш-устойчиво:
`notify` игнорирует unwatch не-смотренного — логировать, не падать). Событие
`fs-change` получает payload `{ "path": "<абсолютный путь>" }`.

Фронтенд: матчинг пути события по корням (тот же `resolveRoot`-принцип),
refresh только затронутого дерева, дебаунс 300 мс на корень (как сейчас).
Канонизация путей (регистр букв, разделители) — на стороне сравнения, обе
стороны пропускаются через нормализатор.

Альтернатива N watcher'ов отклонена: больше ресурсов, никакой выгоды.
Проверка любых правок watcher'а — только с рестартом `tauri dev` (урок §11).

### D6. Файл workspace: чтение/запись существующими командами

Формат:

```json
{ "version": 1, "folders": [ { "path": "./project", "color": "blue" } ] }
```

Чтение/запись — существующие `readFile`/`writeFile` (JSON-парсинг в TS), новых
Rust-команд не нужно. В памяти — абсолютные пути; сериализация пересчитывает в
относительные к каталогу файла workspace, когда диск совпадает. Путь последнего
workspace — в persist-слайс `uiStore` (`vasyavig.settings`, рядом с theme/lang).

`grant_asset_scope` вызывается на каждый корень при добавлении (идемпотентен).

### D7. Подтверждения — по образцу существующих `pending*`

`uiStore` расширяется: `pendingRemoveRootPath` (удаление корня с dirty-вкладками
его файлов), `pendingOpenWorkspacePath` / `pendingNewWorkspace` (замена состава).
Существующий `pendingOpenFolderPath` уходит вместе со старым сценарием «открыть
папку вместо». Диалоги — по паттерну `CloseTabModal`.

### D8. Сайдбар: секции-корни

`FileTree` рендерится на каждый корень внутри `RootSection` (заголовок: имя +
color chip + контекст-меню [сменить цвет, убрать из workspace]). Шапка сайдбара
становится workspace-уровнем: «Добавить папку», «Открыть workspace», «Новый
workspace». Блок «Текущая директория» Phase 6 демонтируется — его роль
переходят к заголовкам секций.

## Risks / Trade-offs

- [Селекторы Zustand, создающие объекты на каждый вызов → «белое окно» §3] →
  аудит всех новых селекторов на примитивы/стабильные ссылки; производные
  (`resolveRoot`, списки корней для рендера) — только `useMemo`; тест на
  ре-рендер в vitest.
- [Windows-пути: регистр, `\` vs `/` в матринге префиксов и событиях watcher'а]
  → единый нормализатор путей, применяемый к обеим сторонам сравнения; тесты на
  кейсы `C:/docs` vs `C:/DOCS`, `C:/docs2`.
- [Шквал fs-событий в большом дереве] → пер-корневой дебаунс (сейчас 300 мс
  глобальный — сохранить величину, скоуп на корень).
- [Внешняя правка workspace-файла при работающем приложении] → last-write-wins
  при следующей автозаписи; осознанный trade-off (Non-Goal).
- [Рамка/тинты ломают скролл-цепочки §8] → `outline` вместо `border`; тинты
  только `background-color`, без `overflow` на корневых элементах Gravity.
- [Рассинхрон вкладок и корней при удалении корня] → единая точка: экшен
  `removeRoot` сам закрывает вкладки корня после подтверждения.

## Migration Plan

Пользовательских данных для миграции нет: единственный корень ранее не
персистился (в localStorage только theme/lang). Первый запуск с фичей — пустой
workspace; пользователь добавляет папки и получает файл workspace при первом
добавлении. Откат — реверт ветки, сторы обратно к `rootPath`.
