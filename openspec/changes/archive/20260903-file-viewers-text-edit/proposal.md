# Proposal: просмотр изображений и .eml, редактирование текстовых файлов

> Дата: 2026-09-03 | Статус: draft
> Контекст: чекпойнт `_docs_/_checkpoints_/20260902_002_checkpoint.md`, беклог
> `_docs_/roadmap.md` (пункты «Просмотр графических файлов», «Редактирование
> текстовых файлов в Monaco»), запрос пользователя 2026-09-03.

## Why

Сейчас изображения и файлы `.eml` определяются как `unsupported` — их невозможно
открыть из файлового дерева, хотя документация, с которой работает пользователь,
содержит и то, и другое. Текстовые файлы (`.txt`, `.sql`, `.json` и т.п.)
открываются в Monaco только в read-only: чтобы поправить конфиг или скрипт,
приходится уходить во внешний редактор. Всё это ломает сценарий «одна папка
документации — одно окно приложения».

## What Changes

- **Просмотр изображений в отдельной вкладке**: png/jpg/jpeg/gif/webp/bmp/svg/ico
  открываются из дерева (клик/двойной клик, Ctrl+O, drag-and-drop) в вкладке
  с вписыванием в область и зумом (кнопки «+/−», Ctrl+колесо, переключатель
  «вписать / 100%»). Отображение — только локальных файлов через asset protocol
  (инфраструктура Phase 5); SVG рендерится через `<img>`, без выполнения
  скриптов; вкладка просмотра никогда не dirty.
- **Просмотр `.eml` в отдельной вкладке** (read-only, plain-text): заголовки
  From/To/Cc/Subject/Date (с декодированием RFC 2047) и тело из части
  `text/plain` (декодирование base64/quoted-printable, кодировки UTF-8 /
  windows-1251 / koi8-r). HTML-тело и вложения не рендерятся — осознанное
  решение пользователя (минимальный состав).
- **Редактирование текстовых файлов**: Monaco для text-вкладок снимает
  read-only; появляются dirty-индикатор, Ctrl+S, «Сохранить как» (Ctrl+Shift+S),
  «Сохранить все» — с той же семантикой, что у markdown-вкладок. Первая правка
  закрепляет preview-вкладку (спека preview-tabs, без изменений).
- Новые виды вкладок работают в существующих потоках: табы, закрытие с промптом
  только при dirty, переименование/удаление файлов, статус-бар, заголовок окна.
- **Вне скоупа**: реакция открытых вкладок на внешние изменения файла (watcher
  сейчас обновляет только дерево) — единый механизм для markdown и text-вкладок
  вынесен в беклог как отдельный change.

## Capabilities

### New Capabilities

- `image-viewer`: открытие графических файлов в вкладке-просмотрщике — whitelist
  форматов, отображение через asset protocol, вписывание и зум, read-only.
- `eml-viewer`: открытие `.eml` в вкладке-просмотрщике — разбор MIME, показ
  заголовков и text/plain-тела, кодировки, read-only, graceful-деградация.
- `text-file-editing`: редактирование текстовых файлов в Monaco — dirty-статус,
  сохранение (Ctrl+S / «Сохранить как» / «Сохранить все»), поведение вкладок.

### Modified Capabilities

Нет: preview-tabs-семантика применяется к новым видам вкладок как есть,
требования спеки не меняются.

## Impact

- `src/lib/utils.ts`, `src/lib/constants.ts` — `FileKind` расширяется до
  `image`/`email`, новые списки `IMAGE_EXTENSIONS`, `EML_EXTENSIONS`.
- `src/store/fileStore.ts` — `openFile` не читает бинарный контент изображений.
- `src/store/editorStore.ts` — сохранение для `kind: "text"` (сейчас только
  markdown); image/email-вкладки исключаются из dirty-потоков.
- `src/components/EditorArea/` — новые `ImageViewer`, `EmlViewer`;
  `MonacoViewer` становится редактируемым; `App.tsx` — маршрутизация по kind.
- `src/lib/` — новый MIME-парсер (plain-text скоуп) с тестами; i18n-строки ru/en.
- Rust: единственное добавление — команда `read_file_latin1` (побайтовый
  транспорт для `.eml`, существующий `read_file` строго UTF-8); asset protocol
  и гранты уже настроены (Phase 5).
- `_docs_/roadmap.md` — пункт про внешние изменения файлов добавляется в беклог.
