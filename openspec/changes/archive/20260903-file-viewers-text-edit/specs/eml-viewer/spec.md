# eml-viewer Specification

## Purpose

Просмотр сохранённых электронных писем (файлы `.eml`, формат MIME) в отдельной
вкладке приложения без почтового клиента: заголовки и текстовое тело письма,
включая корректную кириллицу в распространённых кодировках.

## ADDED Requirements

### Requirement: Открытие .eml в отдельной вкладке

Выбор файла `.eml` в файловом дереве, диалог Ctrl+O и перетаскивание файла
в окно SHALL открывать письмо в отдельной вкладке только для просмотра.
Вкладка подчиняется семантике preview-вкладок: одиночный клик — preview,
двойной клик — закрепление.

#### Scenario: Открытие письма из дерева

- **WHEN** пользователь дважды кликает файл `письмо.eml` в дереве
- **THEN** открывается закреплённая вкладка с просмотром письма

### Requirement: Отображение заголовков письма

Вкладка письма SHALL показывать заголовки From, To, Cc (при наличии),
Subject, Date. Заголовки с encoded-words (RFC 2047, кодировки Base64 и
Quoted-Printable, включая windows-1251 и koi8-r) SHALL декодироваться в
читаемый текст.

#### Scenario: Тема с encoded-word в windows-1251

- **WHEN** письмо содержит заголовок
  `Subject: =?windows-1251?B?...?=`
- **THEN** тема отображается читаемым кириллическим текстом

#### Scenario: Отсутствие необязательных заголовков

- **WHEN** письмо не содержит заголовка Cc
- **THEN** строка Cc не показывается (пустые заголовки не выводятся)

### Requirement: Отображение текстового тела письма

Тело письма SHALL браться из первой части `text/plain` (с учётом вложенной
структуры multipart). Content-Transfer-Encoding (base64, quoted-printable,
7bit, 8bit) SHALL декодироваться; кодировка символов (как минимум utf-8,
windows-1251, koi8-r и другие, поддерживаемые платформенным декодером)
SHALL применяться корректно.

#### Scenario: Кириллическое письмо в windows-1251

- **WHEN** тело письма — `text/plain; charset=windows-1251`,
  transfer-encoding — quoted-printable
- **THEN** тело отображается читаемым кириллическим текстом

#### Scenario: Письмо в utf-8 base64

- **WHEN** тело письма — `text/plain; charset=utf-8`,
  transfer-encoding — base64
- **THEN** тело отображается корректно декодированным текстом

### Requirement: Деградация без текстовой части и при ошибках разбора

Если письмо не содержит части `text/plain` (например, HTML-only), вкладка
SHALL показывать сообщение об отсутствии текстовой части вместо пустого
экрана. Если файл не удаётся разобрать как MIME-сообщение, вкладка SHALL
показывать сообщение об ошибке разбора; приложение SHALL продолжать работать.

#### Scenario: HTML-only письмо

- **WHEN** письмо содержит только `text/html`-часть
- **THEN** в вкладке показывается сообщение, что текстовая часть отсутствует
  (HTML не рендерится)

#### Scenario: Повреждённый файл

- **WHEN** пользователь открывает файл `.eml`, не являющийся корректным
  MIME-сообщением
- **THEN** в вкладке показывается сообщение об ошибке разбора, приложение
  не падает

### Requirement: Режим исходника (raw)

Вкладка письма SHALL предоставлять переключатель видов «Разбор / Исходник».
Вид «Исходник» SHALL показывать весь исходный текст файла письма целиком,
включая служебные заголовки (Received, DKIM-Signature, X-* и др.), в
исходном порядке с сохранением фолдинга строк. Не-UTF-8 содержимое SHALL
отображаться best-effort (utf-8, при невозможности — windows-1251).
Переключение не меняет файл и состояние вкладки.

#### Scenario: Просмотр служебных заголовков

- **WHEN** пользователь открывает письмо и переключается в режим «Исходник»
- **THEN** отображается полный исходный текст письма, включая заголовки
  Received и DKIM-Signature

#### Scenario: Возврат к разбору

- **WHEN** пользователь переключается обратно в режим «Разбор»
- **THEN** отображаются декодированные заголовки From/To/Cc/Subject/Date
  и текстовое тело письма

### Requirement: Вкладка письма не редактируется

Вкладка письма SHALL быть только для просмотра: никогда не dirty, Ctrl+S
не выполняет записи, закрытие без подтверждения. HTML-части и вложения
не рендерятся и не сохраняются (минимальный состав по решению пользователя
2026-09-03).

#### Scenario: Ctrl+S на вкладке письма

- **WHEN** активна вкладка письма и пользователь нажимает Ctrl+S
- **THEN** файл не перезаписывается, статус вкладки не меняется
