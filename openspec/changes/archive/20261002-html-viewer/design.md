# Design

## Context

Маршрутизация вкладок по расширению: `getFileKind` (`src/lib/utils.ts`) →
`FileKind` → компонент в `App.tsx`. Просмотровые kind'ы (`image`, `email`)
открываются read-only и не участвуют в сохранении (`isSavableKind` в
`src/store/editorStore.ts`). `.html` сейчас нигде не зарегистрирован
(«unsupported»). Прецедент read-only вьювера с переключателем режимов —
`EmlViewer`. DOMPurify уже в зависимостях; Monaco html-worker уже зарегистрирован
(`src/lib/monacoSetup.ts`). Пример файла-письма: полный HTML-документ
(`<!DOCTYPE html>`, `<head>` с `<title>`, `<body>` с инлайн-стилями), utf-8.

## Goals / Non-Goals

**Goals:**

- Точное отображение самодостаточных HTML-писем «как в почтовом клиенте»
  (инлайн-стили, таблицы, `<pre>`, вложенные списки).
- Изоляция рендера силами платформы (песочница), без новых зависимостей.

**Non-Goals:**

- Редактирование и сохранение HTML-файлов.
- Отображение HTML-части `.eml`-писем (спека eml-viewer сознательно не
  рендерит HTML; пересмотр — отдельный будущий change).
- Открытие ссылок во внешнем браузере (потребует Tauri shell-plugin и
  capabilities; отложено).
- Поддержка не-UTF-8 кодировок HTML и внешних/локальных ресурсов файла
  (картинки рядом с файлом) — файлы по premise самодостаточны.
- Конвертация HTML → Markdown.

## Decisions

### D1. Рендер — `iframe srcdoc` с пустым `sandbox`, без DOMPurify

Просмотр рендерится как `<iframe srcdoc={html} sandbox="" ... />`.

- `sandbox=""` — максимальная изоляция: unique origin, запрет скриптов,
  форм, попапов, навигации (включая переход по ссылкам и meta-refresh).
  Инлайн-стили, таблицы и остальная статика рендерятся штатно.
- Альтернатива «DOMPurify + innerHTML в div» отклонена: теряет контекст
  `<head>`/`<body style>` (стили документа перестают применяться), требует
  доверять санитайзеру каждый тег, а изоляция всё равно слабее (CSS-инъекции
  вида `position:fixed` на весь экран, `javascript:`-links). Песочница
  решает это на уровне платформы (WebView2/Chromium).
- `allow-scripts`/`allow-same-origin` не выдаём никогда; расширение списка —
  только будущим change'ом с явным обоснованием.

### D2. Блокировка внешних ресурсов — инъекция CSP-`<meta>` в srcdoc

`sandbox` не запрещает сетевые загрузки статики (счётчики-пиксели, внешние
картинки). В начало документа инъектируется:

```html
<meta http-equiv="Content-Security-Policy"
      content="default-src 'none'; style-src 'unsafe-inline'; img-src data: blob:; font-src data:; media-src data:">
```

Функция `injectCspMeta(html)` (`src/lib/htmlCsp.ts`): вставка сразу после
`<head...>`, при отсутствии — после `<html...>` как новый `<head>`, при
отсутствии и его — prepend к документу. Консервативный regex, без полного
парсинга; поведение покрыто юнит-тестами (включая файл без head/html).
Альтернатива «CSP приложения целиком» отклонена — влияет на все вкладки и
Tauri-ресурсы.

### D3. Новый `FileKind` `"html"` (не расширение TEXT_EXTENSIONS)

`HTML_EXTENSIONS = ["html", "htm"]` в `constants.ts`; ветка в `getFileKind` и
`getMonacoLanguage` (`html/htm → html`). Read-only семантика вкладки — как у
`email`/`image`: `isSavableKind` не меняется, dirty невозможен, watcher и
preview-вкладки работают без правок. Отдельный kind (а не «text + спец-режим»)
сохраняет текстовые вкладки редактируемыми и следует сложившейся модели.

### D4. Чтение и режим «Исходник» — штатные механизмы

Файл читается `readFile` (utf-8) в `fileStore.openFile` — без отдельной
ветки. «Исходник» — переиспользование `MonacoViewer` с `editable={false}`
(компонент уже поддерживает read-only режим). Переключатель
«Просмотр / Исходник» — локальный `useState` в `HtmlViewer` (как mode-тоггл
`EmlViewer`); в store ничего не добавляем — вид не является состоянием
документа (урок §5: в store — только то, что переживает переключение вкладок).

### D5. Раскладка и тема

`HtmlViewer` — flex-колонка: тоггл режимов сверху, контент снизу. «Просмотр»:
iframe на всю область, фон-подложка `var(--g-color-text-flat)`
(контрастная рамка вокруг «листа» в тёмной теме), iframe имеет белый фон —
документ несёт собственное оформление (включая `<body
style="background:#fff">`), тема приложения на рендер не влияет. Скролл —
внутри iframe (`overflow: auto`).

## Risks / Trade-offs

- [CSP-инъекция ломает экзотический HTML (два `<head>`, XHTML-декларация)]
  → функция вставляет meta только после первого вхождения тега; юнит-тесты на
    типовых формах (полный документ, фрагмент без head, XHTML-пролог).
- [Внешние картинки «пропадают» у пользователя] → осознанное решение
  (privacy: трекинг-пиксели); поведение зафиксировано спекой; ослабление —
  будущий change.
- [Большие файлы в srcdoc] → письма — десятки КБ; атрибут srcdoc спокойно
  принимает такие объёмы, ленивость не требуется.
- [WebView2-специфика `sandbox`/`srcdoc`] → оба атрибута — базовый Chromium,
  используются без флагов; проверка на dev-сборке в задачах.

## Migration Plan

Новая возможность, миграции нет. Откат — удаление ветки kind `"html"` (влияет
только на новые вкладки; сохранённых состояний нет).
