# Spec Delta

## Purpose

Самодостаточность сборки: чистый клон репозитория собирается и работает без
внешних локальных ресурсов (путей за пределами репозитория), а вендоренный
сторонний код документирован и лицензионно чист.

## ADDED Requirements

### Requirement: Чистый клон собирается без внешних локальных путей

Манифесты зависимостей проекта (Rust `Cargo.toml`, npm `package.json`) SHALL NOT
ссылаться на абсолютные локальные пути или каталоги за пределами репозитория.
Сборка на машине, где нет репозиториев автора вне данного клона, SHALL
завершаться успешно (`pnpm install` + `pnpm tauri build`, равно как и
`pnpm tauri dev`).

#### Scenario: Сборка на «чужой» машине

- **WHEN** разработатель клонирует репозиторий на машину без каталога
  `C:/repos/github/anydoc` и выполняет `pnpm install && pnpm tauri build`
- **THEN** сборка завершается успешно; конвертация офисных документов
  доступна в приложении

#### Scenario: Аудит манифестов

- **WHEN** в `src-tauri/Cargo.toml` ищут path-зависимости
- **THEN** все path-ссылки относительные и ведут внутрь репозитория;
  абсолютных локальных путей нет

### Requirement: Конвертация документов работает на вендоренной копии

После вендоринга anydoc конвертация офисных документов
(Word/PowerPoint/Excel/ODF/RTF/EPUB/CSV/PDF) в Markdown SHALL работать как до
него: тот же результат, включая извлечение встроенных изображений в каталог
`<имя>_assets/` и ссылки на них из Markdown.

#### Scenario: Конвертация .docx с изображениями

- **WHEN** пользователь конвертирует .docx со встроенными изображениями
  в Markdown
- **THEN** создаётся Markdown-файл; изображения лежат в `<имя>_assets/`;
  ссылки вида `![...](<имя>_assets/...)` корректны

### Requirement: Вендоренный крейт документирован и лицензионно чист

Вендоренная копия стороннего крейта SHALL содержать оригинальный `LICENSE` и
файл `PROVENANCE.md`, фиксирующий источник (репозиторий и URL), базовый коммит
апстрима, перечень внесённых изменений (дельта форка), дату вендоринга и
процедуру обновления копии.

#### Scenario: Проверка provenance

- **WHEN** читают `vendor/anydoc/PROVENANCE.md`
- **THEN** в нём указаны апстрим `firecrawl/anydoc`, базовый коммит v0.2.3
  (`bf3d33e`), дельта форка (`to_markdown_with_assets`), дата и процедура
  обновления

#### Scenario: Обновление вендоренной копии

- **WHEN** в локальном форке anydoc появились правки, которые должны попасть
  в приложение
- **THEN** разработчик выполняет процедуру из `PROVENANCE.md` (переносит
  `src/`, сохраняет правки `Cargo.toml` копии, обновляет записи PROVENANCE.md,
  при необходимости перегенерирует `Cargo.lock`)
